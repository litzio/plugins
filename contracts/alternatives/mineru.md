# MinerU 표본 시험: 시험했고 채택하지 않음(라이선스), 성능 기록

2026-11-13. **Docling 유지**. [사전 기준 a~g](mineru-criteria.md)는 바꾸지 않았다. 첫 시도는 포트 공개 제약 충돌로 미실행했으나, 소유자가 기존 설정의 시작을 허용해 재개했고 이후 라이선스 조건으로 채택하지 않되 pipeline 성능만 기록하도록 범위를 줄였다.

[MinerU 3.4.5 LICENSE.md](https://github.com/opendatalab/MinerU/blob/mineru-3.4.5-released/LICENSE.md)의 **1절 Commercial License and Thresholds**는 계열사 합산 MAU 1억 초과 또는 월 매출 USD 2천만 초과 시 별도 상업 라이선스를 요구한다. **2절 Online Service Attribution Obligation**은 제3자 온라인 서비스에 MinerU 사용 표시를 요구한다. 소유자가 이런 상업 사용 추가 조건이 있으면 채택하지 않기로 했으므로 **g 불충족**으로 판정하며, 해당 기준에 실제로 해당하는지나 HTTP 호출의 법률 효과는 판단하지 않는다.

## 실행과 비교

기존 mineru-api / mineru:latest를 설정 변경 없이 사용했다. 설치 패키지와 API 응답 버전은 **3.4.5**, 라이브 OpenAPI와 `mineru-api --help`를 확인했다. POST /tasks → GET /tasks/{task_id} → GET /tasks/{task_id}/result로 localhost만 호출했다. pipeline, parse_method=txt, formula/table=true, 나머지 처리 옵션 기본값으로 Markdown·content_list·middle_json·model_output·images를 요청했다. 디지털 PDF의 본문은 글자 층 경로지만 표에는 OCR과 수식 모델이 쓰이므로 txt를 모든 글자의 OCR 미사용으로 해석하지 않는다. MINERU_MODEL_SOURCE=local이며 추가 이미지·모델 다운로드, 원격 backend, 외부 AI 호출은 하지 않았다.

[요약 JSON](mineru-summary.json)의 점수는 **같은 기존 score_lsr.py**로 고정 Docling 권장 pdf-en-v2와 MinerU를 재측정한 것이다. [실험 어댑터](../../tools/adapt_mineru_lsr.py)는 content_list의 0~1000 TOPLEFT 좌표, 명시 text_level, middle_json에 묶인 캡션, HTML의 행·열·rowspan/colspan만 옮긴다. level=1은 title, 나머지 명시 단계는 section_header로 매핑한다. furniture 타입은 그대로 분리하고 각주는 임의 추론하지 않는다. 표 셀 범위는 **논리 행·열 병합 범위**로 양쪽에 동일 비교 가능하며 픽셀 셀 bbox는 만들어내지 않았다. HTML/LaTeX의 의미 동등성 정규화는 하지 않아 literal 점수를 의미 오류 수로 읽으면 안 된다. 기존 판정 규칙은 수정하지 않았다.

LSR 실제 4·8·11쪽 이미지와 결과를 대조했다. MinerU는 4쪽 두 단계 병합 머리칸을 보존했지만 원문의 대시 두 칸을 빈 칸으로 만들었고, 11쪽 단위 소문자 s를 대문자 S로 바꿨다. 셀 수식과 위첨자 주석은 HTML 안의 LaTeX 또는 일반 문자로 혼재한다(0.73의 주석 a는 ª, 다른 표의 a는 LaTeX 위첨자). 쪽 넘는 표는 쪽별 별도 표로 남으며 의미 연결은 미판정이다. 첫 식은 원문의 a_k²를 ∂_k²로 잘못 읽고, 둘째 식은 제곱근·첨자·100%가 맞으며, 셋째 식은 세제곱근과 합 범위 j=2..9 및 b_j³를 맞게 보존했다. 두 판 제목 단계·텍스트가 같아서 북마크 유무에 따른 개선은 관측되지 않았다. 숫자 후보 증가는 LaTeX 표현·수식 번호·분할 영향도 포함하며 누락/환각 확정 개수가 아니다.

## 기준 적용과 한계

- a: 불충족. 병합 범위는 개선됐지만 표 내용·숫자 셀은 낮고 수식도 전체 우위가 아니다.
- b: 불충족. 같은 잣대 숫자 셀 보존이 낮고 단위 대소문자 실패도 확인했다.
- c: 축소 지시에 따라 세부 원문 대응 조사 생략. 블록 bbox만 어댑터에 사용했고 출처 사슬 충족을 주장하지 않는다.
- d: 원래 출력 6/17로 Docling 북마크 판보다 낮다. 별도 북마크 보완 가능성은 미평가.
- e: 분류는 존재하나 furniture 대응은 50/65로 부분 충족. 좌표 매칭 진단만으로 본문 유입 개수를 확정하지 않는다.
- f: 충족(pipeline 구조·내용·좌표와 모델 JSON, 세 입력 각 두 번).
- g: 소유자 정책에 따라 불충족(상업 사용 추가 조건).

설치·GPU·최신 버전 차이·문서화 적합성·세부 대응 정보·모델별 라이선스는 축소 요청에 따라 조사하지 않았다. 자동 실행 스크립트가 범위 축소를 즉시 반영하지 못해 pipeline 완료 후 VLM 작업 1건을 제출했으며, 모델 초기화 중 컨테이너를 멈췄다. VLM 결과는 없고 비교에도 포함하지 않았다.

Docker State의 StartedAt=08:34:41.439670121Z, FinishedAt=08:36:57.342461432Z로 켜진 시간은 **약 135.9초**다. 최종 mineru-api와 docling-serve 모두 exited이며 Docling은 시작하지 않았다. 새 이미지·컨테이너·volume·설정 변경 없음, 다른 Docker 대상 변경 없음, 직접 시작한 실행 클라이언트도 종료했다. 원본 응답과 이미지·로그·OpenAPI는 임시 폴더에 보존하고 저장소에는 요약만 넣었다. docs/progress.md는 수정하지 않았다.

표본은 13쪽 합성 문서 하나의 북마크 두 판과 공개 11쪽 발췌이며 MinerU는 기존 3.4.5다. 스캔본·수백 쪽·리치오 실행·다른 버전은 미시험이다. 단회 시간은 성능 벤치마크가 아니고 NIST는 oracle 없이 숫자 후보와 시간·반복만 기록했다. 채점기와 어댑터 단위 검사 총 5개 통과. 진행 기록 인계안: 'MinerU pipeline 표본 시험 완료, 상업 사용 추가 라이선스 조건으로 채택하지 않음. 표 셀 내용·숫자는 Docling 우세, 병합 범위·일부 수식은 MinerU 장점. 다른 변환기는 자유로운 라이선스와 뚜렷한 개선 근거가 생길 때만 재검토.'
