# 변환 옵션 실험과 관찰

2026-11-13, docling-serve 1.38.2-cu128. 이전 서버와 비교하지 않았다. LSR의 두 판에 기준에서 한 항목군씩 바꿨다. 표 preset/mode와 code/formula enrichment는 일관된 한 항목군으로 함께 바꿨다. 모델 초기화·캐시·GPU 변동이 포함된 단회 wall time이며 엄밀한 성능 벤치마크가 아니다. baseline은 cold, repeat는 같은 설정의 warm 실행이다. 표의 수치는 절대 정확도가 아닌 같은 좌표 진단기의 상대 일치 수다. 전체 분모·상태·오류는 [JSON](experiment-results.json)에 있다. 채점 방법과 임의 결과 사용법은 [tools](../../tools/README.md)를 따른다.

## 권장 기본값과 선택 이유

권장 `pdf-en-v2`는 combined다: 기준에서 **images_scale=1**, **do_picture_classification=false**만 바꾼다. 13쪽 두 판 모두 핵심 진단 수가 유지되며 JSON은 약 3.10MB에서 1.38MB로 약 55% 줄었다. warm repeat 21.4/19.4초 대비 combined 20.0/17.3초였지만 단회 변동과 모델 캐시 영향이 있으므로 속도 우위를 일반화하지 않는다. 그림 분류 메타데이터는 후속 문서화에 필수가 아니어서 제외했다. 쪽 이미지는 원문 검수를 위해 유지한다. 배율 2가 필요한 작은 글자 검수는 조정 옵션으로 제공한다.

OCR 끄기는 빠르지만 수식 문자열 진단이 떨어졌다. 강제 OCR은 느리고 일부 furniture·본문 일치를 낮췄다. 표 fast는 셀 내용·숫자 보존이 낮아 accurate를 유지한다. cell matching 끄기는 점수 개선이나 시간 절감 근거가 없어 기존 true를 유지한다. 수식 enrichment 끄기는 수식 내용의 복원이 안 되어 유지한다. 코드만의 효과는 별도로 측정하지 않았고 원래 의도를 유지한다.

제목 추론 켜기는 북마크 있는 판에서 단계 16/17로 flat의 9/17보다 좋지만, 없는 판에서는 3/17로 flat의 9/17보다 낮다. 원래 북마크 활용 의도를 기본값으로 유지하고 사용자가 해당 옵션을 끌 수 있게 한다. 북마크 없는 자료의 정확한 계층은 보장하지 않는다. 추론 세부 플래그는 조정 가능하지만 개별 최적화는 미검증이다.

기준 반복은 두 판 모두 라벨·텍스트·표 내용과 진단 수가 같았다. 일부 표 bbox에 약 0.08pt 미만의 차이가 있어 바이트 동일성은 주장하지 않는다. 같은 입력에서 구조·내용의 실질적 일치는 확인했다.

## 로컬 VLM 한정 시험과 판정

[실행 전 판정 기준](vlm-criteria.md)을 적용했다. OpenAPI의 VLM 기본 preset과 capabilities는 `granite_docling`이며 로컬 모델은 `ibm-granite/granite-docling-258M`이다. 받은 revision은 `982fe3b40f2fa73c365bdb1bcacf6c81b7184bfe`다. 다른 VLM/원격 API는 시험하지 않았다. OpenAPI의 VlmConvertOptions에 force_backend_text가 있어 임시로 custom VLM 설정만 허용하고 로컬 transformers 모델 설정으로 API 요청했다. 라이브러리를 직접 호출해 변환하는 우회는 하지 않았다. 최종 compose에는 이 임시 허용 설정이 없다. 원격 서비스는 시험 내내 비활성이었다.

- **구조 개선(a): 실패.** 기본 VLM 두 판 모두 표 크기 5/8, 셀 범위 107/139, 내용 67/139. 단계형은 8/8, 134/139, 135/139다. 제목 단계는 북마크 있는 판 9/17로 단계형 16/17보다 낮다. 북마크 없는 판은 9/17로 단계형 3/17보다 높아 일부 장점이 있다. 읽는 순서는 125/127이나 대응 가능한 쌍 수가 다르므로 단계형 122/130과 단순 정확도 비교하지 않는다.
- **숫자·부호·단위 보존(b): 실패.** 숫자 포함 셀 문자열은 22/59로 단계형 55/59보다 낮다. backend text도 표 구조와 숫자 셀은 22/59로 같고 일반 숫자 문자열은 25/92로 기본 VLM/단계형 62/92보다 낮았다.
- **원문 대응(c): 조건부 충족.** 기본 VLM의 169개 텍스트·표·그림 모두 prov가 있다. pages.size가 1224×1584로 PDF의 612×792와 달라 쪽 크기 비율로 좌표를 정규화해야 한다. 단계형의 PDF 포인트 좌표와 같다고 취급하면 안 된다. 채점기는 이 비율을 반영하며 관련 단위 검사도 있다.
- **반복(d): 충족.** 기본 VLM은 두 판 모두 첫 실행과 반복 실행의 DoclingDocument가 정확히 같았다. backend text는 구조·숫자 기준에서 이미 탈락해 반복하지 않았다.

판정: **시험했으나 채택하지 않음**. 표·숫자 저하를 계층 일부 개선으로 상쇄하지 않는다. 고정 fixtures는 단계형 권장 결과만 저장한다. VLM 가중치는 모델 volume에 남기고 삭제 여부는 소유자가 정한다.

기본 VLM 125.4~151.0초, 반복 131.5~147.0초, backend text 155.1~158.1초로 단계형보다 느렸다. 결과 JSON도 약 3.15MB/3.13MB였다. 2초 간격 nvidia-smi 관측의 전체 GPU 메모리 최고값은 기본 4711MiB, 반복 4713MiB였다. backend 최고값과 쪽별 숫자 진단은 아래 표/JSON을 따른다. 이 값은 Desktop 화면·캐시 등도 포함하는 대략이며 모델만의 메모리가 아니다. 단계형 실험 중 관측은 약 5221~6219MiB였지만 모델 캐시가 누적된 상태여서 직접 비교할 수 없다.

PDF 글자 층과 숫자/부호 token 다중집합을 직접 비교했다. 벡터 수식은 글자 층에 없고 표·문단 분할도 영향을 주므로 missing/extra는 **검토 후보**이지 환각/누락 확정 개수가 아니다. 단위는 기대 문자열 전체 대조에 포함한다. 원문에 없는 문장·누락 문단의 확정 개수는 전수 시각 대조하지 않아 미측정이다. 좌표 대응 실패나 literal 불일치를 문단 누락이라고 부르지 않는다.

## 눈으로 확인한 관찰과 한계

LSR은 기준의 실제 쪽 이미지 4·11쪽과 결과 JSON을 대조했다. 4쪽의 두 단계 병합 머리칸 구조, 11쪽의 세제곱근 지수·합 범위와 좌우 작은 표를 확인했다. 최종 권장 결과도 같은 위치를 확인한다. 두 입력은 북마크 유무만 다르며 두 결과의 수식·표·읽는 순서 진단은 같지만 계층 단계는 다르다. 수식은 3개가 LaTeX로 나오며 앞 두 식은 읽을 수 있으나 세 번째는 근 지수/합 범위가 틀리고 주변 문장이 섞이는 **확인된 실패 1개**다. LaTeX 문자열 불일치 2개를 곧바로 수학 오류 2개로 해석하지 않는다. 본문과 쪽 아래 주석의 읽는 순서가 기대와 다른 곳이 있으며, 쪽별 인접 순서 불일치 8쌍은 오류 위치 후보로 본다. 위첨자·주석 참조 범위와 쪽을 넘는 표의 의미 연결은 자동 채점하지 않았다.

스캔본·수백 쪽·다른 언어·실제 고객 문서는 시험하지 않았다. 기대 구조는 13쪽 합성 문서 하나의 작성 의도이며 일반 정확도나 최적값을 대표하지 않는다. tableformer_v2, 다른 layout/VLM/OCR preset, 그림 설명·차트 추출은 새 모델 또는 미검증 구성이 필요해 실행하지 않았다. 기본 layout 외 선택지는 현재 capabilities에서 제공되지 않았다.

표 전체 수는 목차 등도 포함해 oracle의 채점 대상 8개와 다르다. 병합 셀은 row_span>1 또는 col_span>1인 출력 셀 수로 셌고 정답 일치 수가 아니다. 주석 참고본은 PDF 자체에 'Not a conversion input'이라고 적힌 시각 정답 자료이므로 소유자 요청대로 변환만 보관하고 원래 좌표 oracle로 채점하지 않았다. 주석 레이아웃 때문에 원본 두 판과 검출 구조가 다르다. 주석 참고본 11쪽을 직접 보았고 주석과 본문을 혼합한 읽는 순서의 전수 적합성은 확인하지 않았다.

최종 LSR 11쪽·무북마크 8쪽 이미지를 확인했다. 위에서 기록한 수식 실패는 최종 결과에서도 같다. LSR 두 판의 furniture는 47개 출력 텍스트로 합쳐져 있지만 기대한 furniture 영역 65개 모두 대응한다. 인접 순서 불일치 후보 8쌍은 주석·다단 내용 검수에 남는다.

NIST는 5쪽 표와 본문, 11쪽 그림·캡션 이미지를 직접 확인했다. 측면 출처 문구 10개와 쪽 번호 11개가 furniture로 분리된다. 출력 표는 8×3, 8×3, 6×3이고 병합 셀은 없다. 5쪽의 표 다음 본문·캡션 순서에서 눈에 띄는 역전은 발견하지 못했지만 11쪽 전체의 읽는 순서를 전수 검증하지 않았다. 마지막 쪽은 가로 그림 중심 자료로 측면 문구가 없어 furniture 21개는 22개 누락을 의미하지 않는다. 작은 그림 내부 글자의 전수 정확도는 확인하지 않았다.

원본 PDF·ground_truth·LICENSES·폰트 고지는 바꾸지 않았다. fixtures 합계는 13,886,395 bytes(약 13.9MB)다. 기존 약 11MB에서 세 입력의 독립 결과와 NIST embedded 이미지를 포함해 늘었지만, 배율 1·이미지 중복 저장 제외로 억제했다. 원문 대조 기능을 유지하려고 쪽 이미지를 없애지는 않았다. 중간 실험·원본 HTTP body는 저장소 외 임시 폴더에 보존했다.
