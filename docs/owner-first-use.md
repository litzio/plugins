# 처음 써 보기: PDF → 검수 → 완료 → 요구사항 인계

최신 공개 리치오 Host·CLI(PluginPublicError 지원 포함)와 Node 24가 필요하다. 작은 PDF 사본으로 시작하고 기존 Docling 서버를 사용한다. CLI_ENTRY/PLUGIN_DIRECTORY/HOST_ORIGIN은 실제 환경 값으로 바꾼다. 설정·입력 JSON은 플러그인 폴더 밖에 둔다.

## 시작 전에 준비할 것

최초 서버 설치·모델 준비는 [서버 안내](../docling-server/README.md)를 따른다. 준비된 환경에서는 소유자가 Docker를 실행한 뒤 저장소 최상위에서 다음 두 줄로 시작·준비 확인한다. 서버가 없으면 PDF 변환부터 시작할 수 없다. 고정 결과를 먼저 써 볼 때는 `fixtures/lsr-1.1/`을 작업 폴더에 **복사**하고 그 사본의 `converted`를 2번에서 고른다(원본 fixtures는 변경·재변환하지 않는다).

```sh
docker compose -f docling-server/compose.yaml up -d
curl --fail http://127.0.0.1:5001/ready
```

## 설치·준비

아래 명령의 PLUGIN_DIRECTORY에 `plugins/docling-convert`, `plugins/docling-to-litzio`, `plugins/requirements-extract`를 차례로 지정해 같은 Host에 설치한다. 요구사항 폴더는 README대로 `npm ci --ignore-scripts`를 먼저 실행한다. 수정 후에는 다시 install한다.

```sh
node CLI_ENTRY plugins install PLUGIN_DIRECTORY --host HOST_ORIGIN --json
```

플러그인 설정에서 변환기의 **서버 주소**, 두 후속 플러그인의 **작업 폴더**를 지정한다. PDF·변환 결과·문서가 작업 폴더 안에 있게 준비하고 앱에서도 **폴더 열기**로 그 폴더를 연다. Host 허용 폴더와 앱에서 연 폴더는 별개다. 앱에서 열지 않으면 문서 미리보기가 거부된다.

## 시작 순서

1. **Docling 변환**에 PDF 경로·실제 쪽 수·새 저장 폴더를 넣고 **변환하고 저장**한다. 완전 성공한 묶음을 사용한다. 중단·불확실한 응답 뒤에는 새 변환을 바로 내지 말고 **기존 작업 상태 확인**으로 관측한다.
2. **Docling 문서 만들기**에서 결과 묶음을 고르고 **입력 확인 → 문서 만들기**한다. 생성·검사 완료는 검수 전 초안이다. 나중에는 **이전 생성**에서 이어 연다.
3. 비서에게 생성 jobId와 묶음 범위를 주고 설치된 **묶음 검수** 스킬로 먼저 검사하게 한다. 비서는 본 자료의 digest로 교정/checkpoint를 남긴다. 평범한 턴 종료에는 stop하지 않으며 사람 판단·규칙 승인을 대신하지 않는다. **교정·진행 새로 읽기**로 남은 범위를 확인한다.
4. **쪽별 기계 대조**에서 기계만 통과한 쪽과 사람이 볼 쪽을 구별한다. **이 쪽 대조** 또는 후보 묶음 대조에서 PDF와 현재 문서를 보고 근거를 적어 확인/보류한다. 잘못된 값은 대조 화면의 교정 제출로 고친다.
5. **표현 변환 규칙**에서 대표마다 **대표 대조 → 원문·문서 열람 기록**을 남긴 뒤 근거를 적고 승인/보류/거부한다. 모든 적용 항목을 펼쳐 볼 수 있다. 주석 연결·기계 검증 실패 등 예외는 항목별 확인에 남는다.
6. 미검사·사람 확인·차단 손실·표현 확인·실패·숫자 차이를 해소하면 **검수 완료**가 활성화된다. 조건은 제출 시 다시 검사한다. 낡은 자료 오류면 대조를 다시 읽는다. 완료 폴더의 문서와 부속 증거를 함께 보존한다.
7. **요구사항 도출**에서 완료 폴더의 `document.md`를 **입력 문서**, 같은 폴더를 **인계 폴더**로 고른 뒤 **후보 준비**한다. **비서에게 판단 맡기기**의 작업 파일을 비서에게 주고 요구사항 후보 스킬을 실행한다. **다시 검사**로 결과를 읽는다. 기계 전용 쪽·규칙 승인 출처는 사람 우선 목록과 상세 출처에 구별되어 남는다. 출처 완료는 요구사항 확정이 아니다.
8. **상위 연결 검토** 후 연결·누락을 검토한다. 상위 문서가 없어도 **상위 미연결 분류**에 독립/범위 밖과 이유를 남긴다. **항목 상세**에서 본문·출처·연결을 보고 **선택 항목 확정**한다. **새 제안 문서 저장 → ReqIF 내보내기**로 새 파일을 만든다. 미확정·지원하지 않는 수식/그림은 정식 출력을 막는다. 시험용 ReqIF는 별도 시험 표시가 있다.

## 알려진 한계·인계

**이 PR 이전의 v1.3 완료 묶음은 읽지 않는다. 다시 검수 완료해야 한다.**

글자 대조는 제목 계층·읽는 순서·의미를 검사하지 않는다. 그림·스캔·도형(표 테두리 포함)이나 미대조 범위가 있으면 사람이 본다. LSR은 사람 쪽 8쪽으로 이전 7쪽보다 줄지 않는다. 표현 29항목은 3규칙+주석 5개로 줄지만 수식 등은 남는다. 일반 문서 탭의 손 편집은 인계를 막으므로 검수 화면으로 교정을 기록한다. actor는 인증이 아닌 제출자의 선언이다.

소비자는 v1.3 완료 조건과 근거를 파일에서 독립 재계산한다. 문서·부속 파일이 바뀌면 옛 요구사항 판단·확정을 그대로 내보낼 수 없다. 일부 LaTeX(예: intertext)는 현재 대조 미리보기에서 오류가 날 수 있어 원문과 보존된 수식도 확인한다. [안내를 따른 실제 Host 기록](../plugins/requirements-extract/docs/v13-first-use.md)은 변환 서버 부재와 결정적 시험 제출을 구분한다. 실제 AI 품질·실제 사람 검수·130쪽 측정은 확인하지 않았다.
