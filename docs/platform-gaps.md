# 리치오에 모자란 것

플러그인을 만들고 쓰면서 리치오 쪽에서 막히거나 돌아가야 했던 것을 잊지 않으려고 적는 장부다. 여기 적는 것은 요청이 아니라 기록이다. 리치오에 실제로 고치자고 올릴지는 소유자가 정하고, 올리면 이슈 번호를 적는다.

## 쓰는 법

- 플러그인 작업 중 리치오의 한계 때문에 돌아가거나 포기한 것이 생기면, 그 PR에서 이 문서에 한 줄을 더한다. 통합 담당자와 작업자 모두 해당한다.
- 한 줄에는 무엇이 안 되는지, 어떻게 알게 됐는지, 지금 무엇으로 대신하는지를 적는다. 해결 방법이나 설계는 적지 않는다.
- 같은 한계를 다른 플러그인이나 다른 문서에서 다시 만나면 새 줄을 만들지 않고 그 줄의 "만난 곳"에 덧붙인다. 여러 번 만난 줄이 먼저 올릴 후보다.
- 리치오에 이슈로 올렸으면 "상태"에 번호를, 리치오에서 해결됐으면 해결된 버전이나 PR을 적는다. 해결된 줄은 지우지 않고 맨 아래 "해결됨"으로 옮긴다.
- 회사와 업무 배경, 고객 자료의 내용, 로컬 경로는 적지 않는다.

상태의 뜻: **기록** — 적어만 둠 / **이슈 #번호** — 리치오에 올림 / **보류** — 일부러 그렇게 만든 것이라 다시 꺼낼 조건을 기다림.

## 문서가 표현하지 못하는 것 (리치오 본체: 문서 의미와 형식)

리치오는 엔지니어링 문서를 담을 수 있어야 한다. 원문에 있는데 리치오 문서로 옮기지 못한 것을 적는다.

| 안 되는 것 | 만난 곳 | 지금 대신하는 것 | 상태 |
| --- | --- | --- | --- |
| 미주의 표시 번호를 문서가 정할 수 없다. 나오는 순서대로 다시 매겨져 원문의 각주 번호와 달라진다. | pdf-import, 표준 문서 PDF. 원본과 나란히 보면 번호가 달라 틀린 것처럼 보인다. | 원문 번호는 잃는다. | 기록(공식 update-footnote는 정의 내용만 바꾸며 표시 번호 지정은 지원하지 않음을 확인함) |
| 순서 목록의 표시 모양을 `(a)`처럼 양쪽 괄호로 쓸 수 없다. | pdf-import, 문단·목록 인식. | 글머리 목록으로 옮기고 항목 글 앞에 원문 표시를 글자로 둔다. | 기록(update-list의 delimiter는 . 또는 )만 허용함을 확인함) |
| 표의 병합 칸·복합 머리글·칸 안 줄바꿈과 표 전용 주석 영역이 없다. | pdf-import, 공식 작성 계약과 글자 표 저장으로 확인함. | 머리글을 합치고 값을 반복하며 주석은 자기 원본 상자를 가진 본문으로 뺀다. | 기록 |
| 표는 100행·32열까지여서 여러 쪽의 긴 표를 하나로 담을 수 없다. | pdf-import, 일곱 쪽에 걸쳐 약 200행인 표와 공식 작성 한도로 확인함. | 쪽마다 표 하나로 저장하며 쪽을 넘는 표를 잇지 않는다. | 기록 |
| 알림 상자에 제목을 붙일 수 없다. 종류 이름표만 보인다. | pdf-import, 표준 문서의 `NOTE 2—` 문단. 작성 계약에 맞춤 제목·옵션이 없음을 확인함. | 원문 `NOTE 2—`를 본문 글자에 그대로 둔다. 이름표 "참고"와 `NOTE`가 겹쳐 보인다. | 기록 |
| 목록 항목 안에 알림 상자를 둘 수 없다. | pdf-import, 표준 문서에서 목록 항목 안에 든 NOTE. 작성 계약의 목록은 중첩 목록 밖의 블록을 받지 않음. | 상자로 빼지 않고 원문 `NOTE—…` 글자를 그 항목 글 뒤에 이어 붙인다. 목록 항목이 문단 여러 개를 담지 못해 별도 문단으로도 둘 수 없다. | 기록 |
| 조항 참조의 표시 문구를 정할 수 없다. `{ref}`는 표시 글자를 받지 않고 제목 대상은 항상 `§ 번호` 또는 `§ 제목 글자`로 보이며, 제목 대상의 `{numref}`도 없다. | pdf-import, 표준 문서의 조항·부록 참조. Core 작성 입력과 읽기 모델의 참조 표시로 확인함. | 조항·부록 참조는 원문 글자로 둔다. 그림·표 참조만 리치오 참조로 바꾼다. | 기록 |
| 공식 작성 입력에 번호 설정(제목 번호, 참조 문구 템플릿)을 넣을 자리가 없다. 작성 입력 최상위는 `title`·`status`·`inputs`뿐이다. | pdf-import, 조항 참조 측정. CLI `update-heading-numbering`은 있으나 플러그인 화면 계약의 같은 호출은 확인하지 못함. | 제목 번호를 켜지 않고 번호를 제목 글자에 둔다. | 기록 |
| 제목 번호 체계에 부록 번호(`Annex B`, `B.1`)가 없다. H1–H6 순번만 있고 고정 번호·접두어·시작 번호를 받지 않는다. | pdf-import, 표준 문서의 부록 제목과 부록 조항. | 제목 번호를 켜지 않고 번호를 제목 글자에 둔다. | 기록 |
| 고정 번호 캡션의 구분자를 정할 수 없다. 리치오가 캡션 앞에 `Figure 3. `를 그리므로 원문의 `Figure 3—` 줄표가 마침표로 바뀐다. | pdf-import, 그림·표 참조. 공식 `inspect`의 `captionNumberText`와 문서 화면으로 확인함. | 캡션 글자에서 원문 번호와 구분자를 떼고 리치오 표시를 받아들인다. | 기록 |
| 그림·표 참조 문구의 번호 앞 빈칸이 U+00A0이다. 화면에서는 같아 보이지만 복사·찾기 글자는 원문의 보통 빈칸과 다르다. | pdf-import, 그림·표 참조. 공식 `inspect`의 `referenceText`로 확인함. | 받아들인다. | 기록 |
| 원문 블록이 원본의 어디에서 왔는지(쪽과 영역)를 문서에 붙여 둘 자리가 없다. | pdf-import. 문서를 고치면 블록 순서에 기댄 대응이 어긋난다. | 문서 옆의 별도 파일에 블록 경로와 좌표를 둔다. 문서가 바뀌면 대응 표시를 멈춘다. | 기록 |

## 플러그인에 내주는 것이 모자란 것 (SDK와 화면 부품)

| 안 되는 것 | 만난 곳 | 지금 대신하는 것 | 상태 |
| --- | --- | --- | --- |
| 넓은 표가 `ui.DocumentView`의 문서 칸에 한 번에 보이지 않아 읽기 불편하다. | pdf-import의 합성 7열 표. 75%·100% 대조 화면과 일반 문서 탭에서 가로 휠로 마지막 열에 닿음을 확인했다. | 가로로 스크롤해 읽는다. | 기록 |
| SDK로 같은 프로세스에서 고쳐도 큰 문서의 오른쪽 갱신이 1.5초를 넘는다. | pdf-import, 격리 HTTP Host에서 2.07~3.10초. 읽기·Core 연산·공식 쓰기·저장본 사후 검사와 문서 보기 다시 읽기를 따로 측정함. | 검사를 유지하고 고치는 중 상태를 표시한다. | 기록 |
| 문서 보기에서 제목의 단계(H2, H3)를 볼 방법이 없다. | pdf-import. 소유자: 오른쪽 문서에서 제목의 깊이를 알 수 없다. | 왼쪽 원본의 제목 상자에 단계를 적는다. | 기록 |
| 화면과 처리 코드가 지금 열린 폴더의 위치를 알 수 없다. | pdf-import, 변환한 문서 목록. | PDF를 골랐던 폴더를 브라우저 저장소에 기억하고 그 폴더들을 찾는다. 새 PC에서는 목록이 비어 있다. | 기록 |
| 플러그인 화면이 폴더 열기를 시작할 수 없다. | pdf-import, 처음 PDF 고르기. 공개 화면 계약의 `pickPath`는 이미 열린 폴더 안에서만 고른다. | 선택에 실패하면 왼쪽 탐색기의 ‘폴더 열기’를 안내한다. | 기록 |
| 공식 화면 저장이 중복 미주 정의 같은 작성 입력 오류를 일반 파일 접근 오류로만 알린다. | pdf-import, 앞 부속을 포함한 PDF 저장. 같은 입력을 공식 CLI create로 검사하면 중복 정의 위치가 나옴. | 개발 검증에서 CLI로 원인을 확인하고, 플러그인이 모호한 각주 짝을 글자로 보존하고 경고한다. | 기록 |
| 공통 ContextMenu에서 비활성 항목의 이유 설명이 열린 동안 첫 Esc는 설명만 닫고 메뉴는 두 번째 Esc로 닫힌다. | pdf-import, 메뉴와 두 항목만 둔 최소 공개 화면에서도 비활성 이유 hover → Esc로 재현함. | 공통 메뉴를 그대로 쓰며 이유가 닫힌 뒤 Esc로 메뉴를 닫는다. 별도 메뉴나 내부 코드 우회는 넣지 않는다. | 기록(PR litzio#1719 포함 Host에서 확인) |
| 화면 코드에 일반 Dialog·Popover 부품을 내주지 않는다. | pdf-import, 쪽 미리 보기 크게 보기. 공개 화면 부품 계약을 확인함. | 격자 자리를 큰 쪽 보기로 바꾸고 닫으면 원래 위치와 focus로 돌아온다. | 기록 |
| 선택 상자 부품이 없다. | pdf-import, 쪽 제외 선택. | 현재 쪽 미리 보기의 ui.Button으로 포함·제외를 바꾼다. | 기록 |
| 플러그인 화면 계약에서 리치오의 UI 언어를 읽을 수 없다. | pdf-import, 변환한 문서 목록의 날짜 표기. SDK 0.11.0 화면 계약을 확인했다. | 플러그인의 기존 한국어 화면 문구에 맞춰 날짜를 표시한다. | 기록 |
| `ScreenLayout width="narrow"`는 본문에만 적용되어 머리의 제목과 동작을 본문 가장자리에 맞출 수 없다. | pdf-import, 변환한 문서 목록 1440px 캡처. | 기존 화면 틀의 전체 폭 머리와 가운데 본문을 사용한다. | 기록 |
| 화면이 파일의 내용을 바이너리로 받는 길이 없다. | pdf-import, 플랫폼 확인. | 처리 코드가 파일 전체를 base64 글자로 넘긴다. 9.4MB에서 약 1초, 넘기는 순간 화면이 0.6초쯤 멈춘다. 더 큰 파일의 한도는 모른다. | 기록 |
| 플러그인의 처리 코드(Node)에 그림을 그리는 기능이 없다. | pdf-import. 표·그림 영역을 그림으로 자르는 일. | 화면에서 그려 저장 기능에 넘긴다. 그래서 변환은 화면이 열려 있어야 하고 CLI만으로는 못 한다. | 기록 |
| 플러그인이 문서가 탭에 열려 있는지, 저장하지 않은 편집이 있는지 알 수 없다. | pdf-import, 대조 화면에서 고치기. 격리 Host의 미저장 탭 아래 저장본에 공식 연산을 실행함. | 저장본을 고치고 탭의 저장 충돌에 맡긴다. | 기록 |
| 공식 convert-block은 본문과 제목 사이의 변환만 제공한다. 목록 항목·캡션으로 바꿀 수 없다. | pdf-import, 대조 화면에서 종류 바꾸기. 공식 도움말로 확인함. 알림 상자(참고)를 본문으로 되돌릴 때도 만남. | 본문과 제목 1~6만 선택하게 한다. 알림 상자는 고치기 대상에서 뺀다. | 기록 |
| 공개 SDK에 알림 상자를 넣는 연산이 없다. 공식 CLI에는 insert-admonition이 있다. | pdf-import, 알림 상자를 문서에서 뺀 뒤 되돌리기. SDK가 내보내는 연산 목록으로 확인함. | 알림 상자의 빼기를 제공하지 않는다. | 기록 |
| 공개 SDK에 문서 제목(머리말 `title`)을 바꾸는 연산이 없다. Core의 `updateDocumentTitle`과 공식 CLI `update-title`에는 있다. | pdf-import, 대제목을 문서 제목으로 보내기. SDK 0.12.0이 내보내는 연산 목록으로 확인함. | 이 동작과 되돌리기만 공식 CLI `apply-batch` 하나로 저장한다. 오른쪽 갱신이 CLI 기동만큼 늦다(LSR 약 0.9초, 큰 문서 약 1.5초 더). | 기록 |
| 공식 insert-footnote는 새 호출 표지를 자동으로 정하고 기존 표지를 지정해 정의를 복원할 수 없다. SDK 0.6.0에도 원래 표지의 정의 복원 연산은 없다. | pdf-import, 마지막 미주 호출이 든 블록을 뺀 뒤 원래 상태로 되돌리기. | 빼기 전 확인하고 되돌리기 기록을 비운다. | 기록 |

## 저장과 설치 (리치오 본체: Host와 공용 작업)

| 안 되는 것 | 만난 곳 | 지금 대신하는 것 | 상태 |
| --- | --- | --- | --- |
| 문서 저장 중 Host 연결 확인이 만료되면 플러그인 화면이 내려가 진행 중인 원본 연결 만들기가 끝나지 않을 수 있다. | pdf-import, 문서와 그림만 남은 사용 중 사례에서 확인했다. | 다음에 PDF를 고르면 남은 문서를 열거나 다시 변환할 수 있게 한다. | 기록 |
| 공식 문서 저장이 기존 이름을 덮어쓰지 않는다. 계약에 일부러 그렇게 적혀 있다. | pdf-import, 다시 변환. | 같은 결과 폴더에 복구 사본을 두고 새로 만든다. 새 저장과 대응 검증이 성공하면 복구 사본과 확인된 불필요한 그림만 정리한다. 실패하면 복구 사본을 보존한다. | 보류. 두 번째 플러그인이 같은 필요를 가질 때 다시 꺼낸다. |
| 플러그인 설치가 명령 여러 개와 설정 화면을 거친다. | pdf-import를 다른 PC에 설치. | 저장소를 받아 의존성을 설치하고 CLI로 설치한 뒤 설정에서 신뢰하고 켠다. | 보류. 저장소 규칙이 설치 배포 체계를 지금 만들지 않기로 했다. |
