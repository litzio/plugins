# 리치오에 모자란 것

플러그인을 만들고 쓰면서 리치오 쪽에서 막히거나 돌아가야 했던 것을 잊지 않으려고 적는 장부다. 여기 적는 것은 요청이 아니라 기록이다. 리치오에 실제로 고치자고 올릴지는 소유자가 정하고, 올리면 이슈 번호를 적는다.

## 쓰는 법

- 플러그인 작업 중 리치오의 한계 때문에 돌아가거나 포기한 것이 생기면, 그 PR에서 이 문서에 한 줄을 더한다. 통합 담당자와 작업자 모두 해당한다.
- 한 줄에는 무엇이 안 되는지, 어떻게 알게 됐는지, 지금 무엇으로 대신하는지를 적는다. 해결 방법이나 설계는 적지 않는다.
- 같은 한계를 다른 플러그인이나 다른 문서에서 다시 만나면 새 줄을 만들지 않고 그 줄의 "만난 곳"에 덧붙인다. 여러 번 만난 줄이 먼저 올릴 후보다.
- 리치오에 이슈로 올렸으면 "상태"에 번호를, 리치오에서 해결됐으면 해결된 버전이나 PR을 적는다. 해결된 줄은 지우지 않고 맨 아래 "해결됨"으로 옮긴다.
- 회사와 업무 배경, 고객 자료의 내용, 로컬 경로는 적지 않는다.

상태의 뜻: **기록** — 적어만 둠 / **이슈 #번호** — 리치오에 올림 / **보류** — 일부러 그렇게 만든 것이라 다시 꺼낼 조건을 기다림.

## 문서가 표현하지 못하는 것 (리치오 본체: 문서 의미와 형식)

리치오는 엔지니어링 문서를 담을 수 있어야 한다. 원문에 있는데 리치오 문서로 옮기지 못한 것을 적는다.

| 안 되는 것 | 만난 곳 | 지금 대신하는 것 | 상태 |
| --- | --- | --- | --- |
| 미주의 표시 번호를 문서가 정할 수 없다. 나오는 순서대로 다시 매겨져 원문의 각주 번호와 달라진다. | pdf-import, 표준 문서 PDF. 원본과 나란히 보면 번호가 달라 틀린 것처럼 보인다. | 원문 번호는 잃는다. | 기록(공식 update-footnote는 정의 내용만 바꾸며 표시 번호 지정은 지원하지 않음을 확인함) |
| 순서 목록의 표시 모양을 `(a)`처럼 양쪽 괄호로 쓸 수 없다. | pdf-import, 문단·목록 인식. | 글머리 목록으로 옮기고 항목 글 앞에 원문 표시를 글자로 둔다. | 기록(update-list의 delimiter는 . 또는 )만 허용함을 확인함) |
| 표의 병합 칸, 표 아래 주석, 쪽을 넘어 이어지는 표를 어디까지 담을 수 있는지 확인하지 않았다. | pdf-import. 지금은 표를 그림으로 넣어 부딪치지 않았다. 표를 글자로 옮길 때 확인해야 한다. | 원본 영역의 그림. | 기록(미확인) |
| 원문 블록이 원본의 어디에서 왔는지(쪽과 영역)를 문서에 붙여 둘 자리가 없다. | pdf-import. 문서를 고치면 블록 순서에 기댄 대응이 어긋난다. | 문서 옆의 별도 파일에 블록 경로와 좌표를 둔다. 문서가 바뀌면 대응 표시를 멈춘다. | 기록 |

## 플러그인에 내주는 것이 모자란 것 (SDK와 화면 부품)

| 안 되는 것 | 만난 곳 | 지금 대신하는 것 | 상태 |
| --- | --- | --- | --- |
| 문서 보기(`ui.DocumentView`)가 스크롤 위치를 알려 주지도 받지도 않는다. 블록이 화면 어디에 있는지, 사용자가 누른 블록이 무엇인지도 알려 주지 않는다. | pdf-import. 소유자: 스크롤이 함께 움직이지 않아 훑어보기 어렵다. 연결선도 그을 수 없다. | 왼쪽을 스크롤하면 `target`으로 오른쪽을 따라오게 하는 한 방향만. | 이슈 litzio#1709 |
| SDK로 같은 프로세스에서 고쳐도 큰 문서의 오른쪽 갱신이 1.5초를 넘는다. | pdf-import, 격리 HTTP Host에서 2.07~3.10초. 읽기·Core 연산·공식 쓰기·저장본 사후 검사와 문서 보기 다시 읽기를 따로 측정함. | 검사를 유지하고 고치는 중 상태를 표시한다. | 기록 |
| 문서 보기에서 제목의 단계(H2, H3)를 볼 방법이 없다. | pdf-import. 소유자: 오른쪽 문서에서 제목의 깊이를 알 수 없다. | 왼쪽 원본의 제목 상자에 단계를 적는다. | 기록 |
| 화면과 처리 코드가 지금 열린 폴더의 위치를 알 수 없다. | pdf-import, 변환한 문서 목록. | PDF를 골랐던 폴더를 브라우저 저장소에 기억하고 그 폴더들을 찾는다. 새 PC에서는 목록이 비어 있다. | 기록 |
| 화면 코드에 일반 Dialog·Popover 부품을 내주지 않는다. | pdf-import, 쪽 미리 보기 크게 보기. 공개 화면 부품 계약을 확인함. | 격자 자리를 큰 쪽 보기로 바꾸고 닫으면 원래 위치와 focus로 돌아온다. | 기록 |
| 선택 상자 부품이 없다. | pdf-import, 쪽 제외 선택. | 현재 쪽 미리 보기의 ui.Button으로 포함·제외를 바꾼다. | 기록 |
| 표 부품(`ui.DataTable`)의 칸에 보조 글씨나 다른 부품을 넣을 수 없고, 열의 필터 아이콘과 개수 표시를 끌 수 없다. | pdf-import, 변환한 문서 목록. 행이 한두 개일 때 군더더기로 보인다. | 이름 뒤에 괄호로 폴더 이름을 붙인다. 아이콘과 개수는 그대로 둔다. | 기록 |
| 화면이 파일의 내용을 바이너리로 받는 길이 없다. | pdf-import, 플랫폼 확인. | 처리 코드가 파일 전체를 base64 글자로 넘긴다. 9.4MB에서 약 1초, 넘기는 순간 화면이 0.6초쯤 멈춘다. 더 큰 파일의 한도는 모른다. | 기록 |
| 플러그인의 처리 코드(Node)에 그림을 그리는 기능이 없다. | pdf-import. 표·그림 영역을 그림으로 자르는 일. | 화면에서 그려 저장 기능에 넘긴다. 그래서 변환은 화면이 열려 있어야 하고 CLI만으로는 못 한다. | 기록 |
| 플러그인이 문서가 탭에 열려 있는지, 저장하지 않은 편집이 있는지 알 수 없다. | pdf-import, 대조 화면에서 고치기. 격리 Host의 미저장 탭 아래 저장본에 공식 연산을 실행함. | 저장본을 고치고 탭의 저장 충돌에 맡긴다. | 기록 |
| 공식 convert-block은 본문과 제목 사이의 변환만 제공한다. 목록 항목·캡션으로 바꿀 수 없다. | pdf-import, 대조 화면에서 종류 바꾸기. 공식 도움말로 확인함. | 본문과 제목 1~6만 선택하게 한다. | 기록 |
| 공식 insert-footnote는 새 호출 표지를 자동으로 정하고 기존 표지를 지정해 정의를 복원할 수 없다. SDK 0.6.0에도 원래 표지의 정의 복원 연산은 없다. | pdf-import, 마지막 미주 호출이 든 블록을 뺀 뒤 원래 상태로 되돌리기. | 빼기 전 확인하고 되돌리기 기록을 비운다. | 기록 |

## 저장과 설치 (리치오 본체: Host와 공용 작업)

| 안 되는 것 | 만난 곳 | 지금 대신하는 것 | 상태 |
| --- | --- | --- | --- |
| 공식 문서 저장이 기존 이름을 덮어쓰지 않는다. 계약에 일부러 그렇게 적혀 있다. | pdf-import, 다시 변환. | 기존 문서와 대응 자료를 이전 사본으로 남기고 새로 만든다. 이전 사본과 옛 그림이 쌓인다. | 보류. 두 번째 플러그인이 같은 필요를 가질 때 다시 꺼낸다. |
| 플러그인 설치가 명령 여러 개와 설정 화면을 거친다. | pdf-import를 다른 PC에 설치. | 저장소를 받아 의존성을 설치하고 CLI로 설치한 뒤 설정에서 신뢰하고 켠다. | 보류. 저장소 규칙이 설치 배포 체계를 지금 만들지 않기로 했다. |

## 해결됨

| 있던 문제 | 해결 |
| --- | --- |
| 리치오가 싣는 pdf.js 5.6.205가 보안 권고 GHSA-hq66-cqwq-w95j의 대상 버전이었다. 플러그인이 같은 패키지를 쓰다가 감사 경고로 알게 됐다. | litzio#1710, PR litzio#1711에서 6.5.438로 올림(2026-11-17 병합, 배포 전). |
| 문서 보기에서 블록에 마우스를 올리면 호버 테두리가 블록과 어긋난 위치에 그려진다. | litzio#1712, PR litzio#1714(2026-11-17 병합, 배포 전). |
| 공식 CLI를 호출해 저장본을 고치고 전후 inspect까지 실행하면 1.5초 안에 화면을 갱신하지 못한다. 호출마다 프로세스 기동 비용이 든다. | litzio#1713, PR litzio#1715(SDK 0.6.0, 2026-11-17 병합·배포 전). 같은 프로세스의 읽기·Core 연산·공식 쓰기로 전환했다. 공개 표본은 0.54~0.64초이며 큰 문서는 2.07~3.10초로 목표 초과가 남는다. |
