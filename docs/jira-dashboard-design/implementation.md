## 개발 가이드

- `litzio-plugin.json`은 공식 설정·PAT·연결 검사와 읽기 전용 `search-issues` 작업을 선언한다. 비서에게 공개한 검색은 프로젝트가 필수이며 키워드는 선택이다. 최대 20개 이슈의 키·제목·상태·원본 링크를 반환한다.
- `host.mjs`가 Host 문맥에서 설정과 PAT를 받고, 설정 변경으로 인스턴스가 종료될 때 요청·캐시를 해제한다. 리치오에서 제공한 `invoke`로 화면과 통신한다. Jira 요청에는 Bearer 헤더를 사용하며 HTTP redirect는 읽기 실패로 처리한다. 사용자 승인에 따라 Base URL과 PAT를 각각 한 번 입력한다. 두 값의 결합 및 교체는 공식 설정의 독립 필드 의미를 따른다.
- `jira.ts`는 엄격한 TypeScript로 작성한 전송부다. 중복 요청 합치기, 요청 취소, 연결별 최대 동시 요청 3개, TTL, 8초 요청 예산, 일시 오류의 최대 1회 재시도, 429 대기를 담당한다. 인증 실패가 발생하면 캐시를 비우며 이전 인증 세대의 응답도 캐시에 들어가지 않는다.
- `workspace.mjs`는 이슈 필드 투영, 페이지·계정·상세 응답 모델, 대시보드 공용 검색과 Count를 담당한다. 목록에서는 상세·댓글·첨부·이력을 조회하지 않는다. Overview의 정확한 KPI는 Jira 검색 응답의 `total`에서 구하고, 분포와 추이는 최근 수정순 50건을 기본 표본으로 한다. 사용자가 Analytics에서 확장한 경우 최대 4페이지, 200건이다. 높은 버전 차이가 예상되는 이력은 해당 탭에서만 요청하고, 최대 응답 크기와 표시 개수를 제한한다.
- `screen.jsx`는 React와 리치오 테마·설정·화면 부품을 재사용한다. 표의 서버 정렬·복수 선택·페이지 이동과 두 계열 차트는 화면에서 구현했다. 보드와 표는 같은 데이터 캐시를 쓴다. 사용자 자동완성은 두 글자부터 350ms 대기한 뒤 최대 15건을 조회하고, 같은 이름의 각 Jira 로그인 식별자를 표시한다.
- 새 문서에는 공식 `pickPath`와 `saveDocument`를 사용한다. 첨부는 메타데이터를 표시하며 파일을 자동으로 받지 않는다. Jira 원문·댓글은 텍스트로 표시한다.

## 호출량과 전송량

63건을 제공한 합성 서버에서 첫 Overview는 조회 1, Count 4, 임박 목록 1로 합계 **6회**였다. 프로젝트 선택기 호출은 별도 1회다. 첫 페이지를 Issues가 재사용한 시점의 추가 호출은 **0회**, 새 페이지는 **1회**, 캐시가 남은 이전 페이지는 **0회**였다. 담당자 조회는 입력 `sam`에 **1회**, 확정한 조건은 **1회**였다. 그 조건으로 Board로 전환할 때는 **0회**였다. 상세와 수동으로 연 댓글·첨부·이력 탭에서 각각 **1회**를 보냈다.

같은 63건 합성 서버를 직접 읽은 Node 테스트에서 첫 Overview의 JSON 본문은 합계 **24,504 B**였다. 목록 22,679 B, Count 각각 106 B, 임박 목록 1,401 B였다. 한 번의 검증에서 개별 로컬 응답 완료 시간은 약 **7~23 ms**였다. Docker의 현재 사용자·2건 페이지 두 개는 각각 190 B·2,351 B·2,399 B로, 약 22 ms·57 ms·53 ms였다. 본문 기준이며 헤더·압축 및 실서비스 지연 시간은 별도다.

같은 합성 서버에서 매번 새 전송부 인스턴스를 만들고 9회 순서대로 실행했다. 지연은 호출별 Jira 전송과 응답 처리를 합한 동작 시간이다. 브라우저 렌더링, Host RPC, 350ms 입력 대기는 포함하지 않는다.

## 남은 수락 범위

실제 기업 Jira와 현행 Docker 목업의 전체 통합 수락은 남아 있다. 기존 목업의 고정된 JQL·필드 계약으로는 임의 검색, 자동완성, 집계·댓글·이력의 지원 경로를 함께 검증할 수 없다. 리치오 공개 계약에서 `invoke` 수준의 취소 신호를 확인하지 못해 화면이 중단한 작업은 별도 취소 작업으로 Host에 전달한다. 공식 비밀값 저장 직후 Host 인스턴스가 전환되는 동안 연결 시험에서 일시적으로 재시도 안내가 나타날 수 있다. 브라우저 실측에는 개발용 Host와 합성 연결을 사용했다.

마지막 필터와 저장 뷰는 소유자가 허용한 예외로 리치오 브라우저 프로필의 `localStorage`를 사용한다. Jira 주소와 계정별로 저장 범위를 구분하고 데모는 별도 범위에 둔다. 저장 항목은 검색 조건과 정렬, 마지막 적용 화면, 사용자가 저장한 뷰다. PAT와 이슈 조회 결과는 저장 대상에서 제외한다.

## SDK 개선 후보

- 플러그인 전용 읽기·쓰기 저장 API를 제공해 저장 뷰와 열 환경설정을 앱 재시작 뒤에도 복원한다.
- 화면의 취소 신호를 Host 작업까지 연결해 별도의 취소 operation 없이 이전 Jira 요청을 중단한다.
- 공식 설정 저장이 새 인스턴스 준비 상태를 표시해, 재시작 중 사용자가 연결 확인을 눌렀을 때 재시도 시점을 알 수 있게 한다.
- 기본 표와 차트에 서버 정렬·열 너비 및 복수 계열 상호작용을 제공해 대시보드 플러그인이 공용 부품을 더 넓게 사용하게 한다.
