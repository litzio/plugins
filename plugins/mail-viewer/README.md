# 메일 열람 (파일럿)

메일 파일(.eml)을 열어 제목, 보낸 사람, 받는 사람, 참조, 날짜, 본문과 첨부 목록을 보여 줍니다. 파일을 읽어 보여 주기만 하며 메일을 보내거나 받지 않고 서버에 접속하지 않습니다. 나중에 지울 수 있는 **파일럿**이라 다른 플러그인이나 저장소 공용 파일에 얽히지 않게 이 폴더 하나에 둡니다. 외부 라이브러리는 쓰지 않습니다.

## 설치와 사용

**GitHub에서 설치:** 설정 → 플러그인 → **GitHub에서 추가…**에 `https://github.com/litzio/plugins`를 넣고 메일 열람을 고릅니다. **로컬 폴더에서 설치:** `litzio plugins install <이 폴더> --host <Host 주소> --json`(폴더는 Host가 허용한 폴더 안).

.eml 파일이 든 폴더를 리치오에서 열고 **메일 열람 → 메일 파일 고르기**로 .eml을 고르면 바로 보입니다. 다른 메일은 **메일 파일 고르기**로 다시 고릅니다.

- 머리: 제목(없으면 `(제목 없음)`), 보낸 사람, 받는 사람, 참조, 날짜. 사람은 `이름 <주소>`이고 받는 사람·참조가 넷 이상이면 처음 셋과 `외 N명`(누르면 모두)입니다. 날짜는 한국 시간 `2026-11-25 14:30`이며 원문 시간대가 +0900이 아니면 마우스를 올려 원문 값을 봅니다. 숨은 참조와 그 밖의 헤더는 보이지 않습니다.
- 본문: `text/plain`이 있으면 그것을 줄바꿈 그대로 보입니다. `text/html`만 있으면 글자로 바꿔 보이고 그 사실을 알립니다. 바꿀 때 스크립트·스타일·머리·주석 등은 내용째 버리고, 문단·제목·표 행은 빈 줄, `<br>`은 줄바꿈, 목록 항목은 `• `, `http(s)`·`mailto` 링크는 `글자 (주소)`로 남기며 나머지 태그(그림 포함)는 버립니다. 화면은 이 글자를 React 글자로만 그리므로 HTML을 실행하거나 원격 자원을 불러오지 않습니다.
- 첨부: 이름·종류·크기의 표. 본문에 끼운 그림(`Content-ID`가 있는 그림)은 종류가 `본문 그림`, 첨부된 메일(message/rfc822)은 그 제목으로 한 줄입니다. 열거나 저장하지 않습니다.
- 실패: `메일 형식이 아닙니다.`, `파일을 읽지 못했습니다.`, `파일이 50MB를 넘어 열지 않습니다.` 중 하나를 알립니다. 일부만 읽혔으면(끝이 잘린 여러 부분 메일, 잘린 base64, 바꾸지 못한 문자 집합) 읽은 만큼 보이고 머리 상태를 `일부만 읽음`으로 하며 무엇이 문제인지 알립니다.

**읽는 것:** 접힌 헤더, 인코딩된 낱말(RFC 2047, 같은 문자 집합의 이웃한 낱말은 이어서 해석), 여러 부분(중첩 포함), base64·quoted-printable·7bit·8bit, 첨부 이름(RFC 2231 이어진 값 포함, 인코딩된 낱말). 문자 집합은 Node의 `TextDecoder`로 바꾸며 utf-8, euc-kr 계열(`ks_c_5601-1987`, `cp949`는 euc-kr로 읽음), iso-8859-1·windows-1252를 확인했습니다. `TextDecoder`가 모르는 문자 집합(예: `iso-2022-kr`)은 추측하지 않고 바꾸지 못했다고 알립니다.

## 하지 않는 것

같은 폴더의 메일 목록, 답장·전달·삭제, 찾기, 정렬, 읽음 표시, 첨부 열기·저장, HTML 그대로 그리기, 원격 그림, `.msg`·`.mbox`·`.pst`, 설정, 비서용 작업과 스킬.

## 확인한 범위

`npm test`는 리치오 없이 표본 다섯([`test/fixtures/`](test/fixtures/README.md))으로 제목·사람·날짜(한국 시간 변환)·본문 글자·첨부 목록과 메일이 아닌 파일의 문구를 검사합니다. HTML 표본은 결과 글자에 스크립트와 원격 그림 주소가 남지 않는지도 봅니다.

격리 HTTP Host(리치오 715df90e, Windows, persistent Chrome, 한국어 UI)에서 처음 화면 → 고르기 → UTF-8 한국어 메일(`외 2명` 누르기) → EUC-KR 한국어 메일(원문 날짜 hover 값) → HTML만 있는 메일(화면에 그림·스크립트 요소 없음, 바깥 주소로 나간 요청 없음) → 첨부 메일(밝음·어두움) → 메일이 아닌 파일을 확인했습니다. 640px에서 가로 넘침은 없었습니다.

확인하지 못한 것: 설치형 Desktop, Windows가 아닌 Host, 실제 메일 프로그램이 저장한 .eml, shift_jis·gb2312 등 그 밖의 문자 집합, 50MB에 가까운 큰 메일.
