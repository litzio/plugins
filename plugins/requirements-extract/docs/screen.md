# 설치와 사람 검토 화면

이 폴더가 설치 단위다. Node 24에서 `npm ci --ignore-scripts` 후, 공개 CLI의 `plugins validate`와 `plugins install`에 이 폴더와 명시적인 `--host`를 전달한다. 플러그인 설정의 **작업 폴더**는 문서·인계·상위 문서·작업 원장을 담을 절대 경로다. 앱에서 그 폴더를 연다. 처리기는 Host의 `context.cli`로 공식 CLI만 실행한다. 별도 CLI 위치나 설치된 daemon을 찾지 않는다.

## 순서

1. **입력 문서**와 선택적인 **인계 폴더**, 상위 요구사항 문서를 공개 `pickPath`로 고른다. 인계가 있으면 선택 문서와 인계 문서가 같아야 한다. 문서만 고르면 저장본 revision·NodePath·원문 인용을 기록하는 native 출처가 되며 PDF 근거는 만들지 않는다. 프로파일은 기본 또는 작업 폴더의 `profiles/*.json` 목록에서 고른다. 유효하지 않은 정책은 선택할 수 없다.
2. **후보 준비** 후 **비서에게 판단 맡기기**로 작업 파일을 만든다. 파일 경로를 복사해 대화에 넘긴다. 파일은 작업 ID와 입력·정책 해시를 담는다. 비서는 설치된 스킬의 공개 CLI 절차로 summary/schema/batch를 읽고 판단을 제출한다. 화면을 읽었다고 가정하지 않는다. 실제 AI 호출이나 자동 판단 코드는 없다.
3. **다시 검사**로 원장 결과를 읽는다. 기본 표는 값·조건 보호 오류, 조건 제외, 문맥 부족, 보류, 교정 출처, 연결 누락·부분 충족을 먼저 묶는다. 문제 묶음 버튼은 해당 후보·요구사항으로 좁힌다. 일반 채택안은 **전체 항목**에서 20개씩 확인한다. 중단은 다음 판단 제출을 막으며 이미 실행 중인 쓰기를 취소했다고 주장하지 않는다.
4. 후보 판단 완료 후 **상위 연결 검토**를 시작하고 비서가 linkBatch/link-submit/gap으로 판단한다. 순위는 연결이나 충족의 증거가 아니다. 상위를 고르지 않았어도 **상위 미연결 분류**에서 독립/범위 밖과 이유를 명시해야 한다. 프로파일의 허용 조건은 처리기가 다시 검사한다.
5. **항목 상세**는 본문·인용·PDF 쪽/영역·교정 전체 이력·연결과 누락 이유·상위 후보를 보여 준다. `DocumentView`는 출처의 저장 revision과 NodePath로 읽기 전용 원문을 나란히 표시한다. **출처 위치**는 다른 출처로 이동하고 다시 읽는다. **원본 문서 열기**는 공개 `openDocument`로 편집 탭을 연다. 저장하지 않은 탭 내용은 이 검토 저장본과 다를 수 있다.
6. 사람은 **선택 항목 확정**, 또는 일반 목록에서 **표시된 채택안 확정**을 누른다. 확정 순간 입력·프로파일·상위 revision·제안 해시를 다시 읽고, 선택 ID에만 confirmedDigest를 기록한다. 변경된 판단과 이전 확정 기록은 자동 복원하지 않는다. 새 제안 문서에는 초안도 남되 실제 확정된 항목만 confirmed가 된다.
7. **새 제안 문서 저장**과 **ReqIF 내보내기**는 같은 공개 작업의 처리기를 호출한다. 파일 이름 충돌은 거부하고 원본은 덮어쓰지 않는다. 저장은 공식 create → target 삽입 → check → inspect/compare → 의미·확정 해시 대조가 모두 통과해야 성공이다. 정식 ReqIF는 모든 대상의 유효 확정·분류·검증 방법과 출처 검수 조건을 다시 검사한다. v1/v1.1 Docling 인계의 unreviewed는 화면에서 승격하지 않으므로 정식 내보내기가 계속 차단된다. **시험용 ReqIF**는 별도 이름과 시험 표시를 갖는다.

제안 문서·ReqIF는 작업 폴더에 새 파일로 저장한다. 처리기의 CLI 경로를 그대로 사용해 target/왕복 검증을 공유하며 화면용 문서 작성기를 따로 두지 않는다. 현재 화면은 출력 하위 폴더 선택을 제공하지 않는다.

## 공개 작업과 실패 경계

| 작업 | 입력 / 결과 |
| --- | --- |
| health | 설정·공식 CLI 가용성 |
| start | `{requestId,action,payload}`. prepare/submit/reopen/links/link-submit/gap/unlinked/task/confirm/save/export/stop/resume |
| inspect | `{requestId,method,payload}`. profiles/summary/detail/batch/schema/linkBatch. 입력 변경 시 원장 갱신 가능성이 있어 write로 선언 |
| job | `{id}` → `{id,state,message,result?}` |
| jobs | 작업 ID·문서 이름·검토 구획 수의 재개 목록 |

긴 일은 Worker에서 실행하고 먼저 queued를 반환한다. 같은 requestId·같은 입력은 저장된 결과를 조회하며 다른 내용의 재사용은 거부한다. succeeded의 result만 성공이다. not_found, Host 재시작 후 완료 응답 없음, 실패는 **쓰기가 없었다는 증거가 아니다**. 원장을 읽어 대조한 뒤 다음 작업을 정한다. 불확실한 쓰기를 새 ID로 자동 재전송하지 않는다. 접수/완료 기록은 서로 다른 새 파일로 남긴다.

작업 원장·원문 snapshot·비서 작업 파일은 작업 폴더의 숨김 하위 폴더에 둔다. 입력·정책 변경은 기존 판단을 무효화하며 이전 연결 작업은 linkHistory에 남긴다. 상위 변경은 기존 연결 판단을 재검토로 돌린다. 기존 연결 작업을 같은 버튼으로 조용히 초기화하지 않는다. 파일이 생성된 뒤 최종 재검사가 실패하면 완료 응답을 성공으로 쓰지 않는다. 남은 파일은 실패 산출물이며 재사용하거나 자동 덮어쓰지 않는다.

## 공개 부품의 한계

실제 확인 기록과 캡처는 [화면 검증](screen-validation.md)에 있다. 화면은 공개 화면 부품·토큰만 쓴다. 한 번에 원문 renderer 하나만 띄우며 출처를 전환한다. `DocumentView`는 셀 경로에서도 표 전체를 강조하고, 지정 높이 480 안에서 스크롤한다. 화면 자체의 세로 스크롤과 함께 사용한다. 여러 renderer를 동시에 띄우는 비용은 측정하지 않았다.

`pickPath`/`openDocument`의 열린 폴더 검사는 공개 계약상 경로 문자열 기준이다. 처리기는 별도로 작업 폴더 밖과 심볼릭 링크 경로를 거부한다. 공개 picker에는 JSON 파일 종류가 없어 프로파일은 검증된 목록으로 고른다. 원문 뷰는 저장본만 읽으며 변경 자동 추적·PDF 영역 표시·셀 하나의 강조를 제공하지 않는다. 출처 위치를 편집 탭으로 함께 전달하는 공개 openDocument 인자도 없다.

공개 DataTable의 가로 스크롤 안내와 달리 실제 화면에서는 overflow가 visible이었다. 긴 좌표·교정 JSON도 열을 넓히므로 상세는 항목별 한 열 표로 구성했다. 후보 목록도 화면의 실제 가용 폭이 좁으면 한 열로 바꾼다. 값을 줄이거나 부품 내부 CSS를 덮어쓰지 않는다.
