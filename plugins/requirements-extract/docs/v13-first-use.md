# v1.3 소비자 연결과 처음 써 보기 기록

소비자는 생산자의 코드를 import하지 않고 파일 계약으로 C0~C9, 내용 결합, 쪽 대조, 규칙 승인 당시 대표·열람과 현재 항목 검증을 다시 계산한다. v1.0~v1.2 판정과 기존 golden은 유지한다. 새 화면·추출 기능·성능 작업은 하지 않는다.

## 확인한 것

- 소비자 단위 검사: 1128건 통과, 조건부 skip 없음. v1.3 36건과 근거 파일·참조 11건은 수동/기계 쪽 완료, 미조사 쪽의 사람 확인 강제, 규칙 영수증 누락·중복·철회·보류·stale, 과거 승인 뒤 독립 교정, 규칙 검증 실패의 개별 확인 복귀, 개별 부정의 우선, 원장 변경에 따른 판단/저장 출처 무효를 포함한다.
- 기존 관련 v1.0~v1.2 90건과 별도 v1.0/v1.1 bytes golden을 유지한다. 생산자 모듈을 가져다 쓰지 않는다.
- 공개 리치오 master `15874db`를 별도 소스 사본에서 빌드했다. 격리 Host에 세 플러그인을 install하고 설정했다. LITZIO_DATA_DIR/LITZIO_ASSISTANT_CWD/LITZIO_ASSISTANT_SETTINGS_FILE/LITZIO_DAEMON_DIR/LITZIO_PLUGINS_SETTINGS_FILE/LITZIO_RESET_DIR을 모두 시험 전용 하위 경로로 지정했다.
- Docker API와 기존 로컬 서버 ready를 읽기로 확인했지만 실행 중이 아니었다. **PDF 변환은 미실행**이다. 서버·컨테이너·이미지를 시작하거나 받지 않았고, 고정 LSR 1.1 결과와 PDF를 사본으로 준비했다. fixtures 원본은 수정·재변환하지 않았다.
- 고정 결과 → 새 문서 생성 → 실제 생산자 완료 발급 → 독립 소비자 requireReviewed 수락을 확인했다. 생산자/소비자 조건 수가 일치했다. 기계 전용은 2/12/13쪽, 미조사 사람 쪽은 4~11쪽이다. 표현 규칙 검증은 병합 10/복합 머리 2/머리 역할 12항목, 주석 5항목은 개별 확인이다.
- 실제 화면에서 폴더 열기, 이전 생성 재개, 대표 PDF·현재 문서 대조, 요구사항 입력 문서와 인계 폴더 선택, 후보 준비를 따라 했다. 나머지 반복 판단은 공개 CLI에 결정적 시험 선언을 제출했다. **실제 AI 판단·실제 사람 검수·의미 품질 확인이 아니다.**

실제 Host에서 25구획·122후보의 결정적 제출을 처리했다. 기계 전용 쪽의 문단 1건과 규칙 승인 병합 셀 값 1건을 채택해, 상위 없음의 독립 분류 → 각각 별도 확정 2건 → 새 제안 문서 저장 → 정식 ReqIF 내보내기를 확인했다. 공개 CLI로 저장 문서를 다시 읽어 전체 source/trace를 상세에서 본 값과 전수 일치시켰고, XML을 별도 파싱해 두 SourceReferences가 기대한 요약·참조 배열과 같은지 검사했다. 각 값은 289/5523자, ReqIF 전체는 30,741 bytes다(성능 측정이 아닌 산출물 크기). 전체 근거는 18개 파일에 보존했다.

근거 파일 한 개를 손상시킨 뒤 저장 문서 reader의 source-trace-reference 오류와 공개 정식 내보내기 거부·새 ReqIF 파일 미생성을 확인하고 원문 bytes를 복원했다. 단위 검사는 다른 폴더의 상위 출처도 출력 위치의 근거 저장소에 결합하는 경계와 invalid UTF-8의 U+FFFD 오인 재사용을 거부한다. 실제 Host에서 상위 문서가 있는 조합은 별도로 실행하지 않았다.

## 막힌 곳과 미확인

서버가 없어 신규 PDF 변환에서 시작하는 단계는 막혔다. 소유자 서버 시작 두 줄과 고정 결과부터 시작하는 경로를 [사용 안내](../../../docs/owner-first-use.md)에 적었다. LSR의 intertext 수식은 대조 화면에서 KaTeX 미리보기 오류를 보였다. 이 조각에서 수식 렌더러를 바꾸지 않는다. 실제 비서 재시험·실제 소유자 확정·130쪽 통제 측정·도형 분류표·수백 쪽 성능은 수행하지 않았다.

실제 끝단에서 trace 24KB가 문서 셀 16,384자 상한을 넘었다. 소유자 결정대로 문서에는 요약·ID·digest, 전체 trace는 플러그인 자료로 옮겼다. 이후 SourceReferences 389,256자가 기존 ReqIF STRING 65,535 한도를 넘었으므로 ReqIF도 요약·참조만 사용한다. 한도를 확대하거나 문자열 분할을 하지 않는다. [근거 참조 형식](source-traces.md)을 따른다. ReqIF 파일만으로는 전체 근거가 따라가지 않는다. 같은 표의 손실·규칙 승인·열람·검증 자료가 문맥의 셀 출처 17개에 반복되어 큰 JSON이 됐으며 이번에는 중복 구조를 고치지 않는다.

초기 시험 드라이버의 rule-material 응답을 raw 자료로 잘못 읽은 부분과, 선택한 두 값 모두 규칙 승인 표에 속한다는 가정을 고쳤다. 공개 결과의 material 객체를 사용하고 기계 전용 문단/규칙 승인 병합 셀을 명시적으로 선택한다. 시험용 선언을 실제 열람·승인 품질로 보고하지 않는다.

재현 도구는 `validation/v13-first-use.mjs CLI_ENTRY WORKSPACE HOST_ORIGIN generate|finalize|consumer`다. 이미 격리·설치·설정한 Host와 작업 폴더 사본의 lsr/converted를 사용한다. finalize는 결정적 시험 사람 선언을 기록하므로 소유자의 실제 검수 폴더에 실행하지 않는다.
