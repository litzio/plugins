# PR20 재검토: 표시한 것과 처리한 것의 결합

상세를 읽은 뒤 같은 ID의 본문이 바뀌어도 요약만 새로 읽으면 옛 본문과 새 확정 해시가 섞일 수 있었다. 후보 목록 또한 채택된 요구사항이 하나라도 생기면 나머지 후보를 빼서 보류 묶음의 개수와 행이 달랐다.

공개 confirm은 상세가 돌려준 reviewed를 필수로 받는다. 판단 원장 head·입력·정책·연결/누락 판단의 revision, 제안·요구사항·상세의 해시, 원문 revision/NodePath를 현재 상세와 전부 대조한다. 새 요약 해시를 함께 보내도 옛 reviewed는 거부한다. 확정 기록에도 해당 근거를 남긴다. 이전 버전에서 reviewed 없이 기록한 확정은 유효 확정으로 세지 않는다. 이 값은 변경 감지용이며 사람 승인을 증명하는 서명은 아니다.

summary.review가 문제 목록, 각 행의 모든 관련 대상, 개수, 페이지를 함께 만든다. 문제 한 건이 한 행이다. 중복 후보처럼 대상이 여럿이면 같은 행에서 상세 대상을 고른다. 빈 구획·전역 오류처럼 대상이 없어도 행은 남긴다. 화면은 처리기가 준 행을 다시 합치거나 필터하지 않는다. 전체 목록에는 채택된 요구사항과 나머지 후보가 함께 남는다.

## 화면 사본·계산 점검

| 위치 | 처리 / 회귀 검사 |
| --- | --- |
| 상세 사본과 새 summary | 낡음 표시 후 다시 읽기. confirm은 summary가 아닌 표시한 상세의 reviewed를 전송. 공개 작업에서 현재 값과 대조. 새 본문·같은 ID + 새 요약/옛 상세 혼합 제출 거부 |
| 제목 목록의 일괄 확정 | 본문을 표시하지 않은 확정 경로를 제거. 상세를 보고 선택 항목만 확정 |
| 문제·후보 필터, 개수, 페이지 | 처리기가 만든 review.groups/all/pages를 그대로 표시. 모든 그룹에서 count = rows.length = 전체 페이지의 실제 렌더 행 수. 복합 대상·23개 같은 후보의 문제·대상 없는 오류도 검사 |
| 표 부품의 필터·정렬 사본 | revision·목록·페이지가 바뀌면 표를 새로 마운트. 사용자가 한 목록에서 건 필터가 다른 묶음의 행을 숨기지 않도록 하네스에서도 상태를 가진 표 대역으로 검사 |
| 행·그룹·페이지 전환 중 상세 응답 | 선택 변경 시 상세 요청 세대를 바꿔 늦은 응답을 버림. 페이지 전환의 첫 대상 번호도 처리기의 페이지에서 받음 |
| DocumentView 상태 사본 | 현재 상세와 출처 읽기 회차의 callback만 받음. 다른 상세·같은 상세의 다른 출처·다시 읽기 전 뷰의 ready를 무시. 같은 상세 재읽기도 renderer를 다시 읽음 |
| 비동기 summary / 중복 실행 | 진행 중 UI 작업을 ref로 직렬화. 상세 응답을 요청 당시 작업·revision과 대조 |
| 비서 작업 파일 표시 | 작업 ID·revision이 같을 때만 표시. 작업 전환·revision 변경 시 화면 사본 제거. 이미 만든 파일의 삭제나 취소를 주장하지 않음 |
| 재개 목록의 중복·집계 | Host가 작업별 목록을 내며 작업 파일 영수증이 검토 개수를 덮지 않음. 화면은 기록 당시 수라고 표시하고 재개 때 fresh summary를 읽음 |
| 프로파일 목록·입력 경로 | 선택을 위한 초안. prepare/fresh의 기존 정책·revision 검증을 유지하며 화면 사본을 판정 근거로 사용하지 않음 |
| 연결 시작·상위 없음 판단·저장·내보내기 | 목록의 reviewRevision을 필수로 제출하고 공개 작업에서 검사. 저장 처리도 검사한 같은 상태를 사용. 기존 재읽기·정식 내보내기 차단 유지 |
| 본문·교정·관계 표시 | 처리기의 값에 대한 표시만 수행. 분류·도출 이유도 상세에 표시. 표시한 구조와 출처 전체를 detailDigest로 결합 |

## 검증의 구분

React 하네스는 실제 screen.jsx를 변환해 React hooks·이벤트로 실행한다. 공개 ui 부품과 CLI 경계는 검사 대역이며 실제 renderer/Host를 대신 검증했다고 하지 않는다. 두 리뷰 재현, 모든 그룹·페이지의 행, 늦은 상세/원문 뷰 callback, 비서 작업 파일의 낡은 사본을 검사한다. 처리 코드 검사는 reviewed의 각 필드를 삭제/변경하고, 본문은 같지만 누락 이유가 바뀐 경우도 거부하는지 확인한다.

`validation/screen-reviewed.mjs setup/change/hold`는 별도의 실제 공개 CLI 경로다. 공개 고정 텍스트로 native 문서를 새로 만들고 결정적인 판단을 제출한다. 같은 ID의 본문에 다른 원문 문맥을 명시적으로 적용한 뒤 새 요약 해시 + 옛 reviewed의 거부를 확인한다. hold 단계는 실제 처리기의 채택 1/보류 1 상태를 만든다. 기존 `screen-safety.mjs`와 `screen-links.mjs`도 새 목록·상세 근거를 제출해 재검증했다. 두 ReqIF는 XSD·독립 파서 왕복을 통과했다. 실제 AI는 호출하지 않는다.
