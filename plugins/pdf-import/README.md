# PDF 가져오기

글자 층이 있는 PDF를 리치오 문서로 만들고, 원본 쪽과 저장된 문서를 나란히 봅니다. 변환 서버와 AI 모델은 쓰지 않습니다.

## 설치와 사용

**필요한 Host: SDK 0.8.0과 PR litzio#1725를 포함한 리치오(7e399625 이후, 2026-11-17 병합·배포 전).** 공개 ContextMenu와 Select hideLabel, PR litzio#1716의 문서 스크롤·클릭 보고를 사용합니다. 플러그인 선언에는 최소 SDK 버전 필드가 없습니다.


Node 24 환경에서 이 폴더의 `npm ci --omit=optional`를 실행합니다. `node prepare.mjs`는 고정된 pdf.js worker 문자열을 다시 만듭니다. 공식 CLI에서 대상 Host를 명시하여 `litzio plugins install <이 폴더> --host <Host 주소> --json`으로 설치합니다.

PDF가 든 폴더를 리치오에서 열고 **PDF 가져오기 → PDF 고르기**로 파일을 고릅니다. 다음은 전체 폭의 **뺄 쪽 고르기** 격자입니다. 격자는 제외 제안을 기다리지 않고 열립니다. 제안이 도착하면 직접 바꾸지 않은 쪽에만 적용합니다. 누르거나 Shift 범위로 바꾼 쪽은 사용자의 선택을 유지합니다. 제안 확인 중에도 변환을 누르면 그때 고른 대로 진행합니다. 이전 파일의 저장된 제외 선택은 바로 적용합니다. 128px 미리 보기를 누르면 포함·제외가 바뀌고 Shift로 범위를 고릅니다. 키보드 Enter·Space와 Shift도 같습니다. 쪽 번호 아래에는 그 쪽의 첫 책갈피 제목을 한 줄로 표시하며 hover·focus로 전체 제목을 확인합니다. 책갈피가 없으면 번호만 표시합니다. **취소**는 파일을 고르기 전으로 돌아갑니다.

미리 보기에 hover·focus하면 **크게 보기** 아이콘이 보입니다. 크게 보는 동안 이전·다음 쪽 버튼이나 좌우 화살표로 넘기고 포함·제외를 바꿀 수 있습니다. Esc나 닫기로 원래 격자 위치와 focus에 돌아옵니다. 범위 조작 설명은 격자 상태 글의 hover·focus에, 큰 쪽의 단축키는 해당 버튼의 hover·focus에 표시합니다. 공개 화면 부품에 일반 Dialog·Popover가 없어 격자 자리를 큰 쪽으로 바꾸는 방식을 씁니다.

**변환**을 누르면 PDF 폴더 아래 PDF 이름의 폴더를 만들고 그 안에 같은 이름의 `.md`와 `.pdf-source.json` 대응 자료, `assets/`의 그림을 만들고 원본과 저장본을 나란히 보는 **대조 화면**으로 갑니다. 대조 화면에는 쪽 고르기 조작이 없습니다. 도구 줄 오른쪽의 이전·다음은 모든 경고를 순회하며 현재 번호와 이유는 그 아래 한 줄에 표시합니다. 경고 종류 필터는 없습니다. 머리 줄에는 PDF 고르기·다시 변환·문서 열기만 둡니다. 원본 상자를 누르면 문서 블록을 강조합니다. 함께 스크롤은 기본으로 켜져 있으며 양방향으로 동작합니다. 원본 스크롤이 멈추면 강조 없이 문서가 따라오고, 문서를 스크롤하면 맨 위에 보이는 블록의 원본 상자가 왼쪽 높이의 1/3 지점에 옵니다. 최근 휠·스크롤바·스크롤 키 입력을 받은 칸이 주인이며 반대쪽의 늦은 보고는 무시합니다. 함께 스크롤을 끄면 양쪽 모두 따라가지 않습니다. 오른쪽 블록을 누르면 원본의 같은 블록이 선택되고 해당 동작 줄과 강조가 표시됩니다. 이 누르기는 함께 스크롤을 꺼도 동작하며 문서를 다시 읽지 않아 더블클릭한 글자 선택을 유지합니다. 원본 대응이 없는 블록은 스크롤 때 가장 가까운 앞 대응을 쓰고 누르기는 무시합니다. 문서가 바뀌었거나 고치는 중이면 보고를 무시합니다. 따라가는 블록은 왼쪽 띠 색, 누른 선택은 옅은 면과 바깥의 가는 선으로 구분합니다. 제목은 H1~H6, 목록은 변환 결과에 2 이상 단계가 있을 때 여백에 단계를 표시합니다. 문서 열기는 일반 탭을 엽니다.

첫 화면의 **변환한 문서** 행을 고르면 PDF를 다시 고르지 않고 저장본을 엽니다. 목록은 이 브라우저가 Host별로 기억한 최근 10개 PDF 폴더의 바로 아래 PDF별 폴더의 대응 자료를 읽습니다. 폴더 하나가 목록 한 항목이며 더 깊은 폴더는 찾지 않습니다. 원본이 없거나 바뀌면 상태를 표시하고 자동 변환하지 않습니다. 같은 이름은 폴더 이름 하나로 구분합니다. 새 PC나 브라우저 자료를 지운 뒤에는 그 폴더에서 PDF를 한 번 고르기 전까지 목록이 비어 있습니다. 공개 계약에 현재 열린 폴더를 조회하는 기능이 없어 최근 폴더 방식을 사용합니다.

제외한 쪽은 흐린 원본 위에 반투명 대각선 **제외** 글자와 위험색 테두리로 표시합니다. 대상 정보에는 떨어진 제외 범위도 표시하며 다섯 구간을 넘으면 개수만 표시합니다. 제외 목록은 대응 자료에 보관합니다.

변환한 문서 목록에서 저장본을 열면 바로 대조 화면으로 갑니다. PDF 고르기로 이전 파일을 고르면 그때 저장한 제외 선택이 적용된 격자로 갑니다. 대조 화면의 다시 변환은 확인 후 같은 선택의 격자로 돌아갑니다. 변환을 실행할 때 기존 문서와 대응 자료를 같은 결과 폴더의 `previous` 복구용 사본으로 옮기고 새 문서를 만듭니다. 새 저장과 대응 검증이 끝나면 복구 사본과 쓰이지 않는 이전 그림을 정리합니다. 실패하면 복구 사본을 남기며 자동 복구는 하지 않습니다. 격자를 취소하면 기존 저장본은 바뀌지 않습니다. 그림은 생성 당시 기록한 이름·SHA-256이 일치하는 파일만 지웁니다. 사용자가 수정한 그림과 다른 파일은 보존하며, 결과 폴더에 다른 문서가 있으면 공유 가능성이 있어 이전 그림도 보존합니다. 문서를 고쳤으면 대응 이동을 막습니다. 대응 자료를 잃은 기존 문서는 자동 덮어쓰지 않습니다.

짝이 맞는 각주는 공식 미주로 저장합니다. 동일 번호의 정의가 여러 개면 모호한 호출과 모든 정의를 글자로 보존하고 각주 짝 경고를 붙입니다. 정의 없는 표시는 `[n]` 글자로, 표시 없는 정의는 해당 쪽의 문단으로 보존하고 경고합니다. 표·그림은 원본 영역 PNG이고 캡션은 작성 입력의 그림 캡션을 사용합니다. 인식할 영역이 없는 독립 캡션은 문단으로 남습니다. 캡션은 Table/Figure 번호 뒤의 줄표·하이픈·마침표·쌍점을 인식하며, 보통 글자는 같은 쪽의 인접 영역이 있어야 합니다. Figure 아래 작은 글자의 축 줄만 사이에 있으면 영역을 아래로 넓혀 PNG에 포함합니다. 본문 크기의 줄을 넘어서 연결하지 않습니다.

## 확인 범위

`npm test`는 리치오 없이 공개 LSR 표본의 제목·글자 분류·제외·쪽 간 문단·결과 형태, 쪽 제외 제안과 선택한 쪽의 글자·그림 제외, 짝 없는 표시, 영역 합치기와 각주 공백 보존, 캡션과 축 포함, 같은 크기 각주 번호·쪽 간 짝 맞추기, 최근 폴더 목록의 원본 변경·삭제를 검사합니다. 실제 격리 HTTP Host에서 공개 표본과 별도 큰 디지털 PDF의 선택·변환·저장·강조·전체 스크롤을 확인했습니다. 저장본 재사용, 확인 후 이전 사본 보관, revision 변경 시 이동 차단, 640px 안내와 밝고 어두운 테마를 확인했습니다. 공개 표본 캡처는 `test/captures/`에 있습니다.

OCR, 스캔 PDF, 표의 문자화, 글자 교정, 옵션과 설정 화면은 없습니다. 패키징된 Desktop, 다른 OS·폰트·회전/세로쓰기 PDF, 변환 중 종료 뒤 복구는 검증하지 않았습니다. 같은 쪽에서 크게 겹치는 영역은 읽기 순서와 무관하게 하나로 합치고, 그 밖의 연속 도형은 본문·제목·캡션·각주가 경계가 됩니다. 공개 표본에는 영역 밖 축 글자의 본문 혼입, 옆에 놓인 표의 합침, 수식 도형과 본문의 분리, 작은 글자 본문의 각주 포함은 큰 줄 간격을 경계로 고쳤습니다. 여러 단 이름 목록과 나란한 표의 주석 합침은 남아 있습니다. 원문 각주 번호와 리치오가 표시하는 미주 번호는 다를 수 있습니다. 저장본을 불러올 때 revision을 확인하고 이후 stale-target 알림이 오면 이동을 막습니다.

직접 의존성은 Apache-2.0의 `pdfjs-dist` 6.5.438 하나입니다. pdf.js worker와 `PDFJS-LICENSE`는 같은 배포물에서 가져옵니다. 스크립팅은 계속 끕니다. `npm audit`에서 취약점 0건을 확인했습니다.

`npm ci --omit=optional` 설치 상태에서 추출과 검사를 실행했습니다. 선택적 canvas와 그리기 전역에 관한 pdf.js 경고는 나지만 글자·도형 추출에 사용되지 않아 전역 대체는 추가하지 않았습니다.

`node measure.mjs <PDF>`는 문서를 저장하지 않고 추출·규칙을 실행해 제목·각주·캡션 등의 검증 통계를 JSON으로 출력합니다. 저작권 입력의 통계와 내용은 저장소 밖에서만 보관합니다.

이번 화면 변경은 격리 HTTP Host에서 공개 표본의 쪽 선택·Shift 범위·키보드 선택·재변환 확인·목록 재열기와 경고 필터를 확인했습니다. 각주 정의가 든 쪽을 제외한 경우도 통합된 각주 짝 판정을 사용합니다. DocumentView의 공개 경로 보고와 target을 사용하며 내부 에디터나 스크롤 DOM에 접근하지 않습니다.

## 문단과 목록 판정

본문 크기(±0.6pt) 글자들의 기준선으로 줄 간격을 잽니다. 쪽마다 긴 본문 줄의 오른쪽 끝 90백분위수를 구하고 1.25em 이내를 가득 찬 줄로 봅니다. 그 비율이 45% 이상이면 양끝 맞춤으로 판정합니다. 평소 기준선 간격의 1.45배를 넘는 간격, 0.7em을 넘는 들여쓰기 변화는 문단을 나눕니다. 양끝 맞춤에서 짧은 줄은 문단을 끝내며 줄 끝 하이픈은 이어짐의 보조 신호입니다. 겹치는 문자 조각의 기존 조립은 유지합니다. 쪽 끝의 가득 찬 줄은 다음 쪽 본문과 잇고, 신호가 어긋날 때만 `paragraph-boundary` 경고와 이유를 남깁니다. 소문자 시작 자체는 경고가 아니며 `용어: 설명`도 정상입니다.

목록은 기호·순서 표시와 내어쓰기 위치를 보존하며, 같은 높이에 떨어진 표시와 본문을 합칩니다. 변환 블록의 `marker`, `level`, `contentX`에 표시와 단계를 담습니다. 공식 작성 입력의 순서 목록(style/start/delimiter)과 중첩 목록을 사용합니다. `(a)`처럼 지원하지 않는 표시는 글머리 목록 항목 글자에 그대로 둡니다. 연속 목록을 묶은 경우 각 원본 항목은 저장된 최상위 목록 경로에 대응합니다. 단독 `i)`는 뒤의 `ii)`가 없으면 영문자로 해석하는 모호성이 남습니다.

`node compare-paragraphs.mjs <PDF 또는 변환 결과 JSON> <비교 자료 JSON> [첫 쪽]`은 개발용 경계 비교입니다. 비교 자료는 Docling의 texts 또는 공개 표본의 elements를 받습니다. 영문자·숫자로 정규화한 25자 이상 문단·목록의 앞뒤 22자를 같은 쪽 ±1에서 비교합니다. 목록 표시는 새 변환 블록의 marker로 본문에서 분리하며, 비교 자료에서 여러 쪽에 반복되는 머리글을 제외합니다. 원문과 비교 자료는 포함하지 않습니다.

공개 LSR 정답의 문단·목록 부분을 CC0 표본으로 두고 경계를 검사합니다. 이 표본은 가득 찬 줄 약 33%의 오른쪽이 들쭉날쭉한 문서입니다. 경계 비교는 각주 뒤 본문 두 개를 분리하여 33/46에서 35/48이 되었으며, 기존의 영역·수식·쪽을 넘는 정답 단위 차이도 분모에 남습니다. 이름만 배치한 명부를 표시가 있는 목록으로 추정하지 않습니다. 큰 PDF와 공개 표본은 격리 HTTP Host에서 목록을 포함한 문서 저장 및 대응 자료 생성을 확인했습니다. 다단 본문과 임의 순서 표시를 폭넓게 검증한 것은 아닙니다.

각주 짝은 블록 조립 뒤 실제 저장 대상의 문단·목록·제목·번호 없는 제목 후보·캡션 전체에서 다시 셉니다. 작성 계획도 전달받은 블록 목록으로 재판정하므로, 정의가 제거된 표시는 `[n]` 글자와 각주 짝 불일치 경고로 남습니다. 참조가 없어진 정의는 원래 위치의 문단으로 남습니다. 완성된 작성 입력의 중첩 목록·그림 캡션까지 순회해 같은 입력 안에 정의가 없는 미주 호출이 있으면 번호를 담은 오류로 저장 전에 중단합니다. 공개 표본에서 정의 블록을 제거한 경우와 입력 간에만 정의가 존재하는 경우를 검사합니다. 통합한 쪽 제외 화면에서 각주 정의가 든 쪽을 제외한 뒤 저장하고, 남은 호출이 글자와 경고로 보존되는 것도 확인했습니다.

## 대조 화면에서 고치기

원본 상자를 누르고 Shift로 범위를 고릅니다. 고칠 수 있는 원본 상자의 우클릭·Shift+F10·메뉴 키는 공통 ContextMenu를 엽니다. 선택 안에서 열면 여러 선택을 유지하고, 선택 밖에서 열면 그 블록 하나로 바뀝니다. 메뉴와 도구 줄은 같은 조건·이유·동작을 쓰며 쓸 수 없는 항목의 이유는 hover·focus로 보입니다. 메뉴의 종류는 본문으로·제목 1~6으로 나열하고 같은 종류는 비활성입니다. 표·그림·제외 상자에는 메뉴가 없고 고치는 중이나 대응이 바뀌면 열리지 않습니다. 메뉴를 닫거나 실행하면 원본 상자로 focus가 돌아오며, 뺀 상자는 다음 대응 상자로 옮깁니다. 동작 줄의 **합치기**는 이웃한 본문을, **나누기**는 본문 하나의 둘째 원본 줄부터 처리합니다. **종류**에서 본문·제목 1~6을 고르고 **문서에서 빼기**로 본문·제목·목록을 제외합니다. 표·그림 영역, 목록 항목·캡션으로의 변환은 지원하지 않습니다. 목록 여러 항목이 같은 문서 블록에 묶였으면 개별 항목을 빼지 않습니다. Esc는 줄 선택을 취소합니다. **되돌리기**는 이 화면의 직전 동작부터 복원합니다. 각주 호출이 든 블록을 빼면 정의가 사라질 수 있고 공식 SDK에 원래 표지를 지정한 정의 복원 연산이 없어 확인 후 처리하며 되돌리기 기록을 비웁니다.

대응 자료의 줄 자료·문서 종류·고친 표시와 이력은 저장됩니다. 옛 위치와 옛 형식의 결과는 지원하지 않습니다. 같은 프로세스의 공식 SDK `readDocument`로 문서와 revision을 읽고, Core 연산을 적용한 뒤 `writeDocument`로 한 번 저장합니다. 사전 revision·블록 수·종류 검사와 쓰기의 revision 충돌 거부를 유지합니다. 저장 직후 SDK로 저장본을 다시 읽어 반환 revision·블록 수·종류를 검사하고 실제 인라인 스냅샷을 대응 자료에 보관한 뒤 화면에 반환합니다. 이 사후 검사는 쓰기용 읽기와 별도이며, 화면 뒤로 미루지 않습니다. 원본 상자와 오른쪽 문서는 확인 결과를 받은 뒤 함께 갱신합니다. 어긋나면 대응 이동을 멈추고 되돌리기는 남깁니다. 화면을 닫으면 되돌리기 기록은 없어집니다. 문서를 탭에서 고치는 중인지 SDK가 알 수 없어 저장본 수정은 허용됩니다. 미저장 탭에서 나중에 저장하면 충돌로 거부되므로 먼저 저장하거나 닫은 뒤 대조 화면에서 고치세요.

단위 검사는 `npm test`로 실행하며 SDK 없는 환경에서는 통합 검사 하나를 건너뜁니다. SDK 통합 검사는 공개 SDK를 해석할 수 있는 환경에서 필요한 TypeScript loader를 사용하고, `PDF_IMPORT_TEST_CLI_ARGS`에 공식 CLI 실행 인자 배열(JSON)을 지정하여 `node --test test/corrections-host.test.mjs`를 실행합니다. CLI는 검사 문서 생성과 최종 유효성 검사에만 쓰며 교정·조회는 SDK로 실행합니다. 줄 글자와 문서의 글자·미주 호출을 공백 차이만 허용하여 전체 대조하며 위치를 확정하지 못하면 나누지 않습니다.

격리 HTTP Host에서 공개 표본의 합치기·되돌리기·다시 합치기·나누기·종류 변경과 되돌리기·빼기와 되돌리기를 확인했습니다. 오른쪽 문서 ready까지 0.54~0.64초였습니다. 큰 문서의 같은 흐름은 2.07~3.10초여서 1.5초 목표를 충족하지 못했습니다. 큰 문서에서 26회 연속 교정 중 plugin process failure는 재현되지 않았습니다. 공개 표본의 7가지 교정과 각각의 되돌리기는 master의 CLI 경로와 문서 바이트 및 사후 검사가 끝난 대응 자료 전체가 같았습니다. 각주 호출 삭제는 기존과 같이 확인 후 되돌리기 기록을 비우며, 원래 표지를 지정한 정의 복원 기능은 여전히 제공하지 않습니다. 처리 코드에 남은 CLI 호출은 없습니다. 설치형 Desktop은 검사하지 않았습니다.

## 원본의 영역 표시

일반 블록은 종류별 옅은 면과 왼쪽 띠로 표시합니다. 마우스나 키보드 focus에서는 면이 진해지며, 선택선은 글자 영역에서 4px 떨어집니다. 스크롤 추적은 띠 색만 바꿉니다. 경고·단계·고침은 왼쪽 여백에 나란히 둡니다. 줄 선택선은 나누기 중에만 표시합니다. 제외 영역은 빗금으로 구별하고 hover와 focus에서 제외 이유를 표시합니다. 설명은 조작 줄 아래의 예약된 공간에 있어 원문을 덮지 않습니다. 종류별 색과 조작 방법은 같습니다.

격리 HTTP Host의 공개 표본에서 7쪽 각주 선택 전후, 다중 선택, 나누기, 머리글·바닥글과 사용자가 뺀 영역, 단계·경고·고침의 동시 표시, 표와 그림, 밝고 어두운 테마를 확인했습니다. 종류별 면은 토큰 색 12%, hover/focus 18%, 선택 22%를 곱하기 혼합으로 표시합니다. 혼합은 쪽 단위로 묶습니다. 제외는 text-muted 70%와 surface 30%를 섞은 회색에서 80% 빗금 선(2px, 주기 7px)과 35% 면을 만듭니다. 제외 영역만 사방 3px 넓혀 작은 머리글·바닥글에서도 무늬가 보이게 합니다. 범례도 같은 무늬입니다. 임의 PDF의 극히 좁은 왼쪽 여백과 본문까지 겹친 원본 상자는 확인하지 않았습니다. 설치형 Desktop은 이번 변경에서 검사하지 않았습니다.

## 쪽 고르기의 검증과 비용

격리 HTTP Host에서 공개 표본(책갈피 있음/제거한 사본)과 별도 138쪽 PDF로 선택 → 격자 → 변환·대조, 누르기·Shift 범위·크게 보기·키보드 조작, 취소·다시 변환·저장본 바로 열기를 확인했습니다. 공개 표본 캡처는 `test/captures/page-picker/`입니다. 범위 선택과 공개 PDF의 첫 책갈피 대응은 리치오 없이 검사합니다.

미리 보기는 화면과 300px 주변만 그리며 동시에 두 장까지 그립니다. 지나간 쪽은 대기·진행 중 그리기를 취소합니다. 완성된 캔버스는 격자를 닫을 때까지 재사용합니다. 138장을 그린 뒤 왕복 스크롤에서 크기 재설정 0건을 확인했습니다. 크게 보기는 해당 쪽만 큰 배율로 그립니다.

SDK 0.6.0 Host의 1440×1000 창에서 128px·8열로 24장이 완전히 보이고 일부가 보이는 것까지 32장입니다. 첫 화면 완료는 5.52초에서 1.75초로 줄었습니다. 파일 전달 0.56초, PDF 준비 0.12초, 책갈피 대응 0.01초였고 제안은 별도로 진행합니다. 완성된 138장으로 왕복했을 때 재그리기 0건, 전체 격자 스크롤의 50ms 초과 long task는 17회·최대 71ms였습니다. 캔버스 픽셀 저장량은 약 11.2MiB이며 GPU·프로세스 전체 메모리 값은 아닙니다.

처리 코드는 같은 sha256의 추출 Promise와 결과를 한 파일분만 메모리에 보관합니다. 제안 완료 뒤에는 기존에도 추출을 다시 하지 않았습니다. 이제 제안 추출 도중 변환을 시작해도 같은 작업을 기다리며 중복 추출하지 않습니다. 같은 선택의 변환은 변경 전 14.48초, 변경 후 13.30초였으며 둘 다 추출 대기는 약 0ms였습니다. 이 차이를 추출 재사용에 의한 개선으로 해석하지 않습니다. 제안 응답을 끝까지 보류하고 그 전에 시작한 변환은 남은 추출 대기 2.11초를 포함해 14.96초였습니다. 저장된 제외 선택이 사용자 선택 그대로이고, 늦은 응답이 대조 화면을 바꾸지 않는 것을 확인했습니다.

제안 응답을 늦춰 직접 포함·제외와 Shift 범위를 먼저 바꾼 경우도 확인했습니다. 앞 부속을 포함한 변환에서 발견한 중복 각주 정의는 F-07로 기록했고, 모호한 짝을 글자로 보존하여 공식 저장과 CLI 검사를 통과했습니다. 설치형 Desktop, 다른 OS, 회전·세로쓰기·가로세로가 혼재한 대형 PDF는 검증하지 않았습니다.

## 양방향 대조 검증

PR litzio#1716을 포함한 격리 HTTP Host에서 공개 표본과 별도 큰 PDF의 양쪽 휠·스크롤바·키보드 이동, 번갈아 조작하기, 함께 스크롤 끄기, 오른쪽 제목·문단·목록·표·그림 누르기와 고친 뒤 새 대응을 확인했습니다. 오른쪽 누르기로 선택한 문단을 합치고 되돌린 뒤에도 이동했습니다. 더블클릭한 단어 선택이 유지됐습니다. 공개 표본의 일부 대응을 비운 시험 자료에서 누르기는 기존 선택을 유지하고 스크롤은 바로 앞 블록의 원본을 사용했습니다.

큰 PDF에서 1800px 휠 이동마다 120ms와 두 animation frame을 기다리며 처음부터 끝까지 측정했습니다. 50ms 초과 long task는 왼쪽 15회·최대 107ms, 오른쪽은 새로 연 PDF에서 25회·최대 109ms였습니다. 앞선 순회로 그림이 준비된 상태의 오른쪽은 0회였습니다. 이전 왼쪽 기록 33~34회·최대 99~108ms와 비교해 최댓값은 비슷하지만 조작·캐시 조건이 같지 않아 횟수 차이를 성능 개선으로 해석하지 않습니다. 빠르게 끝까지 옮긴 뒤 약 120ms 간격으로 2.3초 동안 두 칸 위치를 기록했고, 왼쪽 주도는 263ms 이후, 오른쪽 주도는 137ms 이후 안정적이었습니다. 소유권 해제를 위한 고정 대기는 없으며 기존 왼쪽 스크롤의 150ms 모음만 유지합니다. 실제 터치패드의 관성 스크롤, packaged Desktop과 다른 OS는 검증하지 않았습니다.

`answer-key-baseline.json`은 종류별 맞음의 하한입니다. `npm test`가 이를 읽으며, 개선하는 PR에서 기준선을 올립니다. F-06은 각주 다음 줄의 빈 간격이 앞 각주 글자 크기의 2배를 넘으면 정의를 끝냅니다(새 번호 정의는 계속 허용). T-09는 같은 높이의 영역 오른쪽에 있는 괄호 숫자만의 줄을 영역에 포함하고, 사이 또는 뒤에 같은 높이의 본문이 있으면 합치지 않습니다. 수식 영역끼리 또는 표와 수식이 합쳐지는 기존 T-05는 남습니다.

이번 변경은 처리 코드·단위 검사와 정답 채점만 검증했습니다. Host 설치·화면·PNG 자르기 실행은 하지 않았으며, 수식 번호를 포함한 영역 좌표를 검사했습니다. 다른 폰트·회전 문서와 큰 줄 간격을 실제 각주 내부에 쓰는 문서는 확인하지 않았습니다.

## 가벼운 위쪽 줄과 블록 메뉴

도구 줄 왼쪽은 범례와 선택 동작을 바꿔 보이고, 오른쪽은 경고 이동·함께 스크롤·되돌리기를 한 묶음으로 둡니다. 되돌리기는 기록이 있을 때만 한 자리에 나타납니다. 종류 선택은 공개 Select의 hideLabel을 쓰며 접근성 이름은 유지합니다. 도구 줄은 32px 버튼 한 줄이고, 그 아래 안내는 24px 한 줄을 늘 차지합니다. 나누기 안내가 경고 이유보다 우선합니다. 내부 폭이 850px 이하면 오른쪽 묶음을 다음 줄로 보내 범례와 선택 동작 사이의 높이 차이를 막습니다.

지정 격리 Host에서 공개 표본의 선택 없음·하나·여러 개·나누기·경고 이동·되돌리기 상태에서 원본 칸 시작 높이가 같은 것을 확인했습니다. 1440·1000·900·800px 창에서 가로 넘침과 겹침을 확인했습니다. 메뉴에서 합치기·나누기·종류·빼기와 되돌리기를 실행했고, 메뉴 안의 비활성 이유와 키보드 진입·focus 복귀를 확인했습니다. 공개 표본 캡처는 test/captures/top-bar-context-menu/에 있습니다. 실제 터치패드·packaged Desktop과 다른 OS는 확인하지 않았습니다.

공통 메뉴에서 비활성 이유 설명이 열린 동안에는 첫 Esc가 이유만 닫고 두 번째 Esc가 메뉴를 닫는 것을 최소 화면에서도 확인했습니다. 이유가 닫혀 있으면 Esc 한 번으로 닫히며 focus는 원본 상자로 돌아옵니다. 이 한계는 docs/platform-gaps.md에 남겼습니다.

## PDF별 저장

`X.pdf`는 원래 위치에 두고 `X/X.md`, `X/X.pdf-source.json`, `X/assets/`에 저장합니다. 그림 key는 문서에 나오는 표·그림 전체 순서로 `table-001`, `figure-002`처럼 정합니다. 실제 파일은 같은 이름의 `.png`이고, 기존 이름에 다른 내용이 있으면 Host 계약에 따라 내용 해시 8자리가 붙습니다. 원본 위치는 대응 자료의 PDF 이름과 결과 폴더의 부모로 찾습니다. 이전 평면 저장 위치를 찾거나 변환하는 코드는 없습니다.

시각은 PC 시간대에 관계없이 한국 시간 `YYYY-MM-DD HH:mm:ss`입니다. 고친 이력과 목록의 수정 시각이 이 형식을 씁니다. 날짜만 필요한 값은 같은 함수의 `YYYY-MM-DD` 형식을 사용합니다.

이번 변경은 격리 HTTP Host에서 공개 LSR와 책갈피를 제거한 LSR 사본을 같은 입력 폴더에서 변환했습니다. 각각 그림 10개가 별도 assets에 저장되고 대조 화면·일반 문서 탭에서 표시됐으며 합치기·되돌리기와 목록 재열기를 확인했습니다. 재변환 전후 모두 문서 1개·대응 자료 1개·그림 10개였고 복구 사본은 남지 않았습니다. 큰 디지털 PDF에서도 저장과 그림 정리를 확인했습니다. 실패 후 수동 복구, 다른 OS와 packaged Desktop은 확인하지 않았습니다. 터치패드·터치 입력은 검사 범위가 아닙니다.
