# PDF 가져오기

글자 층이 있는 PDF를 리치오 문서로 만들고, 원본 쪽과 저장된 문서를 나란히 봅니다. 변환 서버와 AI 모델은 쓰지 않습니다.

## 설치와 사용

Node 24 환경에서 이 폴더의 `npm ci --omit=optional`를 실행합니다. `node prepare.mjs`는 고정된 pdf.js worker 문자열을 다시 만듭니다. 공식 CLI에서 대상 Host를 명시하여 `litzio plugins install <이 폴더> --host <Host 주소> --json`으로 설치합니다.

PDF가 든 폴더를 리치오에서 열고 **PDF 가져오기 → PDF 고르기**로 파일을 고릅니다. **제외할 쪽을 고른 뒤 변환**을 누릅니다. 첫 번호 제목 이전 쪽은 제외 제안으로 미리 골라져 있으며 사람이 바꿀 수 있습니다. 쪽의 선택 상자나 쪽 그림을 누르면 제외 여부가 바뀌고 Shift로 범위를 고릅니다. 키보드 Enter·Space와 Shift도 지원합니다. 같은 폴더에 같은 이름의 `.md`와 `.pdf-source.json` 대응 자료, `assets/`의 그림을 만듭니다. 이전·다음은 고른 경고 종류만 순회하고 현재 이유를 위쪽에 표시합니다. 원본 상자를 누르면 문서 블록을 강조합니다. 함께 스크롤은 기본으로 켜져 있으며 원본 스크롤이 멈춘 뒤 문서가 따라옵니다. 문서를 스크롤해도 원본은 움직이지 않습니다. 따라가는 상자는 얇은 포인트 테두리, 누른 선택은 굵은 테두리로 구분합니다. 제목 상자는 H1~H6, 목록은 변환 결과에 2 이상 단계가 있을 때 단계를 표시합니다. 문서 열기는 일반 탭을 엽니다.

첫 화면의 **변환한 문서** 행을 고르면 PDF를 다시 고르지 않고 저장본을 엽니다. 목록은 이 브라우저가 Host별로 기억한 최근 10개 PDF 폴더의 대응 자료를 읽으며 하위 폴더와 이전 사본은 찾지 않습니다. 원본이 없거나 바뀌면 상태를 표시하고 자동 변환하지 않습니다. 같은 이름은 폴더 이름 하나로 구분합니다. 새 PC나 브라우저 자료를 지운 뒤에는 그 폴더에서 PDF를 한 번 고르기 전까지 목록이 비어 있습니다. 공개 계약에 현재 열린 폴더를 조회하는 기능이 없어 최근 폴더 방식을 사용합니다.

제외한 쪽은 흐린 원본 위에 반투명 대각선 **제외** 글자와 위험색 테두리로 표시합니다. 대상 정보에는 떨어진 제외 범위도 표시하며 다섯 구간을 넘으면 개수만 표시합니다. 제외 목록은 대응 자료에 보관합니다. 예전 대응 자료는 당시의 본문 시작 쪽으로 제외 선택을 복원합니다.

동일 PDF의 저장본은 다시 사용합니다. 다시 변환을 누르면 저장된 제외 선택으로 돌아갑니다. 선택을 바꾼 뒤 변환을 누르면 확인 후 기존 문서와 대응 자료를 같은 폴더의 `previous` 사본으로 보관하고 새 문서를 만듭니다. 이전 그림은 삭제하지 않습니다. 문서를 고쳤으면 대응 이동을 막습니다. 대응 자료를 잃은 기존 문서는 자동 덮어쓰지 않습니다.

짝이 맞는 각주는 공식 미주로 저장합니다. 정의 없는 표시는 `[n]` 글자로, 표시 없는 정의는 해당 쪽의 문단으로 보존하고 경고합니다. 표·그림은 원본 영역 PNG이고 캡션은 작성 입력의 그림 캡션을 사용합니다. 인식할 영역이 없는 독립 캡션은 문단으로 남습니다. 캡션은 Table/Figure 번호 뒤의 줄표·하이픈·마침표·쌍점을 인식하며, 보통 글자는 같은 쪽의 인접 영역이 있어야 합니다. Figure 아래 작은 글자의 축 줄만 사이에 있으면 영역을 아래로 넓혀 PNG에 포함합니다. 본문 크기의 줄을 넘어서 연결하지 않습니다.

## 확인 범위

`npm test`는 리치오 없이 공개 LSR 표본의 제목·글자 분류·제외·쪽 간 문단·결과 형태, 쪽 제외 제안과 선택한 쪽의 글자·그림 제외, 짝 없는 표시, 영역 합치기와 각주 공백 보존, 캡션과 축 포함, 같은 크기 각주 번호·쪽 간 짝 맞추기, 최근 폴더 목록의 원본 변경·삭제를 검사합니다. 실제 격리 HTTP Host에서 공개 표본과 별도 큰 디지털 PDF의 선택·변환·저장·강조·전체 스크롤을 확인했습니다. 저장본 재사용, 확인 후 이전 사본 보관, revision 변경 시 이동 차단, 640px 안내와 밝고 어두운 테마를 확인했습니다. 공개 표본 캡처는 `test/captures/`에 있습니다.

OCR, 스캔 PDF, 표의 문자화, 문서 교정, 옵션과 설정 화면은 없습니다. 패키징된 Desktop, 다른 OS·폰트·회전/세로쓰기 PDF, 변환 중 종료 뒤 복구는 검증하지 않았습니다. 같은 쪽에서 크게 겹치는 영역은 읽기 순서와 무관하게 하나로 합치고, 그 밖의 연속 도형은 본문·제목·캡션·각주가 경계가 됩니다. 공개 표본에는 영역 밖 축 글자의 본문 혼입, 옆에 놓인 표의 합침, 수식 도형과 본문의 분리, 작은 글자 본문의 각주 포함이 남아 있습니다. 이 변경은 그 부분을 교정하지 않습니다. 원문 각주 번호와 리치오가 표시하는 미주 번호는 다를 수 있습니다. 저장본을 불러올 때 revision을 확인하고 이후 stale-target 알림이 오면 이동을 막습니다.

직접 의존성은 Apache-2.0의 `pdfjs-dist` 6.5.438 하나입니다. pdf.js worker와 `PDFJS-LICENSE`는 같은 배포물에서 가져옵니다. 스크립팅은 계속 끕니다. `npm audit`에서 취약점 0건을 확인했습니다.

`npm ci --omit=optional` 설치 상태에서 추출과 검사를 실행했습니다. 선택적 canvas와 그리기 전역에 관한 pdf.js 경고는 나지만 글자·도형 추출에 사용되지 않아 전역 대체는 추가하지 않았습니다.

`node measure.mjs <PDF>`는 문서를 저장하지 않고 추출·규칙을 실행해 제목·각주·캡션 등의 검증 통계를 JSON으로 출력합니다. 저작권 입력의 통계와 내용은 저장소 밖에서만 보관합니다.

이번 화면 변경은 격리 HTTP Host에서 공개 표본의 쪽 선택·Shift 범위·키보드 선택·재변환 확인·목록 재열기와 경고 필터를 확인했습니다. 각주 정의가 든 쪽을 제외한 경우도 통합된 각주 짝 판정을 사용합니다. 공개 Checkbox 부품이 없어 계약이 허용한 기본 checkbox로 토큰 색을 상속합니다. DocumentView에는 스크롤 위치 조회·설정 기능이 없어 원본에서 문서로만 target 이동을 사용합니다.

## 문단과 목록 판정

본문 크기(±0.6pt) 글자들의 기준선으로 줄 간격을 잽니다. 쪽마다 긴 본문 줄의 오른쪽 끝 90백분위수를 구하고 1.25em 이내를 가득 찬 줄로 봅니다. 그 비율이 45% 이상이면 양끝 맞춤으로 판정합니다. 평소 기준선 간격의 1.45배를 넘는 간격, 0.7em을 넘는 들여쓰기 변화는 문단을 나눕니다. 양끝 맞춤에서 짧은 줄은 문단을 끝내며 줄 끝 하이픈은 이어짐의 보조 신호입니다. 겹치는 문자 조각의 기존 조립은 유지합니다. 쪽 끝의 가득 찬 줄은 다음 쪽 본문과 잇고, 신호가 어긋날 때만 `paragraph-boundary` 경고와 이유를 남깁니다. 소문자 시작 자체는 경고가 아니며 `용어: 설명`도 정상입니다.

목록은 기호·순서 표시와 내어쓰기 위치를 보존하며, 같은 높이에 떨어진 표시와 본문을 합칩니다. 변환 블록의 `marker`, `level`, `contentX`에 표시와 단계를 담습니다. 공식 작성 입력의 순서 목록(style/start/delimiter)과 중첩 목록을 사용합니다. `(a)`처럼 지원하지 않는 표시는 글머리 목록 항목 글자에 그대로 둡니다. 연속 목록을 묶은 경우 각 원본 항목은 저장된 최상위 목록 경로에 대응합니다. 단독 `i)`는 뒤의 `ii)`가 없으면 영문자로 해석하는 모호성이 남습니다.

`node compare-paragraphs.mjs <PDF 또는 변환 결과 JSON> <비교 자료 JSON> [첫 쪽]`은 개발용 경계 비교입니다. 비교 자료는 Docling의 texts 또는 공개 표본의 elements를 받습니다. 영문자·숫자로 정규화한 25자 이상 문단·목록의 앞뒤 22자를 같은 쪽 ±1에서 비교합니다. 목록 표시는 새 변환 블록의 marker로 본문에서 분리하며, 비교 자료에서 여러 쪽에 반복되는 머리글을 제외합니다. 원문과 비교 자료는 포함하지 않습니다.

공개 LSR 정답의 문단·목록 부분을 CC0 표본으로 두고 경계를 검사합니다. 이 표본은 가득 찬 줄 약 33%의 오른쪽이 들쭉날쭉한 문서입니다. 경계 비교는 전후 모두 33/46이며, 기존의 영역·수식·쪽을 넘는 정답 단위 차이도 분모에 남습니다. 이름만 배치한 명부를 표시가 있는 목록으로 추정하지 않습니다. 큰 PDF와 공개 표본은 격리 HTTP Host에서 목록을 포함한 문서 저장 및 대응 자료 생성을 확인했습니다. 다단 본문과 임의 순서 표시를 폭넓게 검증한 것은 아닙니다.

각주 짝은 블록 조립 뒤 실제 저장 대상의 문단·목록·제목·번호 없는 제목 후보·캡션 전체에서 다시 셉니다. 작성 계획도 전달받은 블록 목록으로 재판정하므로, 정의가 제거된 표시는 `[n]` 글자와 각주 짝 불일치 경고로 남습니다. 참조가 없어진 정의는 원래 위치의 문단으로 남습니다. 완성된 작성 입력의 중첩 목록·그림 캡션까지 순회해 같은 입력 안에 정의가 없는 미주 호출이 있으면 번호를 담은 오류로 저장 전에 중단합니다. 공개 표본에서 정의 블록을 제거한 경우와 입력 간에만 정의가 존재하는 경우를 검사합니다. 쪽 제외 UI 자체는 이 변경의 검증 범위가 아닙니다.
