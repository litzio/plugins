# PDF 가져오기

글자 층이 있는 PDF를 리치오 문서로 만들고, 원본 쪽과 저장된 문서를 나란히 봅니다. 변환 서버와 AI 모델은 쓰지 않습니다.

## 설치와 사용

Node 24 환경에서 이 폴더의 `npm ci`를 실행합니다. `node prepare.mjs`는 고정된 pdf.js worker 문자열을 다시 만듭니다. 공식 CLI에서 대상 Host를 명시하여 `litzio plugins install <이 폴더> --host <Host 주소> --json`으로 설치합니다.

PDF가 든 폴더를 리치오에서 열고 **PDF 가져오기 → PDF 고르기**로 파일을 고릅니다. 바로 변환하며 같은 폴더에 같은 이름의 `.md`와 `.pdf-source.json` 대응 자료, `assets/`의 그림을 만듭니다. 이전·다음은 경고만 순회하고 원본 상자를 누르면 문서 블록을 강조합니다. 문서 열기는 일반 탭을 엽니다.

동일 PDF의 저장본은 다시 사용합니다. 다시 변환은 확인 후 기존 문서와 대응 자료를 같은 폴더의 `previous` 사본으로 보관하고 새 문서를 만듭니다. 이전 그림은 삭제하지 않습니다. 문서를 고쳤으면 대응 이동을 막습니다. 대응 자료를 잃은 기존 문서는 자동 덮어쓰지 않습니다.

짝이 맞는 각주는 공식 미주로 저장합니다. 정의 없는 표시는 `[n]` 글자로, 표시 없는 정의는 해당 쪽의 문단으로 보존하고 경고합니다. 표·그림은 원본 영역 PNG이고 캡션은 작성 입력의 그림 캡션을 사용합니다. 인식할 영역이 없는 독립 캡션은 문단으로 남습니다.

## 확인 범위

`npm test`는 리치오 없이 공개 LSR 표본의 제목·글자 분류·제외·쪽 간 문단·결과 형태와 짝 없는 표시 보존을 검사합니다. 실제 격리 HTTP Host에서 공개 표본과 별도 큰 디지털 PDF의 선택·변환·저장·강조·전체 스크롤을 확인했습니다. 저장본 재사용, 확인 후 이전 사본 보관, revision 변경 시 이동 차단, 640px 안내와 밝고 어두운 테마를 확인했습니다. 공개 표본 캡처는 `test/captures/`에 있습니다.

OCR, 스캔 PDF, 표의 문자화, 문서 교정, 옵션과 설정 화면은 없습니다. 패키징된 Desktop, 다른 OS·폰트·회전/세로쓰기 PDF, 변환 중 종료 뒤 복구는 검증하지 않았습니다. 도형이 잘게 나뉜 PDF는 영역이 중복되어 그림이 많아질 수 있습니다. 매 상자 선택은 공식 CLI로 revision을 확인하므로 약 1초가 들 수 있습니다.

직접 의존성은 Apache-2.0의 `pdfjs-dist` 5.6.205 하나입니다. legacy 추출기의 DOMMatrix 초기화를 위해 이 패키지의 선택적 전이 의존성인 `@napi-rs/canvas`(MIT)의 플랫폼 사전 빌드가 필요합니다. 별도 네이티브 빌드는 실행하지 않으며 Node에서는 그림을 그리지 않습니다. pdf.js worker는 같은 배포물에서 생성합니다. `PDFJS-LICENSE`를 함께 배포합니다.

이 고정 버전에는 GHSA-hq66-cqwq-w95j 감사 경고가 남습니다. 스크립팅을 끈 PDF 로드와 canvas 렌더만 사용하며 PDF 스크립트를 실행하는 viewer는 사용하지 않습니다. [상류 권고](https://github.com/advisories/GHSA-hq66-cqwq-w95j)의 우회 설정을 적용했습니다. 다른 의존성 버전으로 자동 갱신하지 않습니다.
