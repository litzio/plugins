# 워드 가져오기

워드 문서(.docx)를 리치오 문서로 옮깁니다. 워드는 제목 단계, 번호, 표, 캡션, 참조 대상을 파일에 적어 두므로 추정하지 않고 그대로 읽습니다. 변환이 끝나면 **원본 쪽과 변환된 문서를 나란히** 놓고, **옮기지 못했거나 바꿔 적은 곳**(확인할 곳)을 넘겨 가며 봅니다. 원본 쪽은 Word가 같은 문서를 PDF로 내보낸 것이고, 변환은 지금처럼 워드 파일에서 합니다. 변환 서버와 AI 모델은 쓰지 않습니다.

## 설치와 사용

**필요한 Host는 SDK 0.12.0과 [litzio#1957](https://github.com/litzio/litzio/pull/1957)(문서 안 링크)을 포함한 리치오(dba55078 이후)입니다.** 그 전의 Host에서도 변환과 저장은 되지만 문서 안 링크를 눌러 이동하지 못합니다.

**GitHub에서 설치:** 설정 → 플러그인 → **GitHub에서 추가…**에 `https://github.com/litzio/plugins`를 넣고 워드 가져오기를 고릅니다. CLI는 `litzio plugins install https://github.com/litzio/plugins/tree/master/plugins/word-import --host <Host 주소> --json`입니다. 직접 의존성은 원본 쪽을 읽고 그리는 Apache-2.0의 `pdfjs-dist` 6.5.438 하나입니다(PDF 가져오기와 같은 버전·같은 방식, worker는 `node prepare.mjs`로 `worker-source.js`에 묶고 `PDFJS-LICENSE`를 함께 둠).

**로컬 폴더에서 설치:** `litzio plugins install <이 폴더> --host <Host 주소> --json`. 폴더는 Host가 허용한 폴더 안에 있어야 합니다.

워드 문서가 든 폴더를 리치오에서 열고 **워드 가져오기 → 워드 문서 고르기**로 .docx를 고르면 바로 변환합니다. 묻는 선택지는 없습니다. 변환 중에는 **구조 읽기 → 그림 만들기 → 문서 저장** 세 단계와 진행 막대(그림 단계는 `그림 i / n`)가 보이고, 실패하면 그 단계에 머물러 원인을 한 문장으로 알립니다.

끝나면 먼저 왼쪽에 **확인할 곳**, 오른쪽에 변환된 문서가 보이고, 그 위에 `원본 쪽 준비 중` 한 줄이 뜹니다. 원본 쪽이 준비되면 화면이 **비교 화면**으로 바뀝니다.

- 왼쪽은 원본 쪽(세로로 이어짐, 보이는 쪽과 앞뒤 두 쪽만 그림)과 블록마다 옅은 상자, 오른쪽은 변환된 문서입니다. `ui.LinkedDocumentView`로 이어 상자와 블록 사이에 띠를 그리고, 한쪽을 누르면 다른 쪽의 짝이 같은 높이로 와서 강조되며, 한쪽을 스크롤하면 다른 쪽이 따라옵니다. 상자 색과 범례는 PDF 가져오기와 같습니다(제목·본문·목록·표·그림).
- 도구 줄 오른쪽의 **확인할 곳 i / N · 이전 · 다음**으로 확인할 곳을 차례로 넘깁니다. 넘기면 양쪽이 그 블록으로 가고, 도구 줄 아래 한 줄에 위치와 설명이 보입니다. 원본 위치를 찾지 못한 블록이면 문서만 가고 그 줄에 `원본 위치 없음`이 붙습니다. 확인할 곳에 해당하는 원본 상자는 왼쪽 띠가 경고 색이고 `!`가 붙습니다. 배율은 100·75·50·40%입니다.
- 화면 폭이 목록·원본·문서 세 칸을 감당하지 못해 비교 화면에서는 확인할 곳 목록 칸을 두지 않고 이 넘기기로 옮겼습니다. 플러그인 화면에 접는 칸 부품이 없고, PDF 가져오기의 `변환 경고 i / n` 넘기기와 같은 자리·같은 모양이라 이쪽을 골랐습니다.
- 원본 쪽이 아직 준비 중이거나 준비하지 못했으면 목록과 문서 화면을 그대로 씁니다. 준비하지 못한 이유는 한 문장으로 보입니다(예: `Word를 찾을 수 없어 원본 쪽을 준비하지 못했습니다.`).

목록 화면에서는 확인할 곳이 종류별로 묶이고, 줄마다 가까운 제목 번호나 캡션과 짧은 설명이 있습니다. 줄을 누르면 오른쪽 문서가 그 블록으로 가서 강조됩니다. 문서 안 링크(원래 REF 필드)는 누르거나 Ctrl+클릭하면 대상으로 갑니다. 머리의 **문서 열기**는 저장된 문서를 일반 탭으로 열고, **다시 변환**은 확인 뒤 새로 만듭니다.

첫 화면의 **변환한 문서** 목록은 이름, 변환 시각, 확인할 곳 수를 보이고, 줄을 고르면 변환하지 않고 그 결과를 엽니다. 원본 쪽과 위치 자료가 있으면 바로 비교 화면이 뜨고, 없으면(이 기능 전에 변환한 문서 등) 그때 준비를 시작합니다. 이미 변환한 워드 문서를 다시 골라도 같습니다. 목록은 이 브라우저가 기억한 최근 10개 폴더의 바로 아래 결과 폴더를 읽습니다(공개 계약에 열린 폴더를 묻는 기능이 없어 PDF 가져오기와 같은 방식).

**저장 위치:** `X.docx`는 그 자리에 두고 `X/X.md`, `X/assets/figure-001.png`…, 확인할 곳과 블록 경로를 담은 `X/X.word-source.json`, Word가 내보낸 원본 `X/X.source.pdf`를 만듭니다. 블록의 원본 위치는 옆 파일의 `source`에 블록별 `{path, kind, page, boxes}`로 더하고(못 찾은 블록은 넣지 않음), 문서 본문에는 좌표를 넣지 않습니다. 옆 파일에는 PDF와 그 PDF를 만든 워드 문서의 SHA-256도 적어, 다시 변환해도 워드 문서가 같으면 PDF를 다시 만들지 않고 위치만 새로 잇습니다. 문서는 초안 상태로 저장됩니다. 다시 변환은 이전 문서와 목록을 복구용 사본으로 옮긴 뒤 새로 저장하고, 확인할 곳까지 연결되면 사본과 더는 쓰지 않는 그림을 지웁니다. 실패하면 사본이 남습니다.

**Word가 필요한 부분(원본 쪽):** 원본 쪽은 Windows에 설치된 Word로 만듭니다. 문서가 저장된 뒤 `X.source.pdf`가 없으면 Windows PowerShell에서 **새 Word 인스턴스**를 보이지 않게 띄워 워드 문서를 읽기 전용으로 열고(최근 파일에 넣지 않음) 제목 책갈피와 문서 구조 태그를 넣은 PDF로 내보냅니다. 사용자가 열어 둔 Word는 건드리지 않습니다. 띄우는 동안 새로 생긴 WINWORD 프로세스가 정확히 하나일 때만 그것을 이번 인스턴스로 보고(PID와 시작 시각을 기록), 하나가 아니면 아무것도 하지 않고 멈춥니다. 끝나면 그 인스턴스만 `Quit()`으로 닫고 30초 안에 끝나지 않으면 그 PID만 끝냅니다. 10분 안에 끝나지 않으면 PowerShell을 멈추고, PID와 시작 시각이 기록과 같을 때만 그 Word 프로세스를 끝냅니다. PDF는 임시 이름으로 쓴 뒤 다 써졌을 때만 `X.source.pdf`로 바꿉니다. Word가 없거나 실패하면 원본 쪽 없이 목록 화면을 그대로 쓰고 이유를 알립니다. 변환과 문서는 영향을 받지 않습니다. 변환한 뒤 워드 문서가 바뀌었거나 없으면 원본 쪽을 준비하지 않습니다.

**원본 위치 잇기:** 블록의 글자를 알고 있으므로, PDF의 글자 층(머리글·바닥글은 Word가 artifact로 표시해 뺌)을 쪽 순서대로 따라가며 같은 글자를 순서대로 찾습니다. 글자와 숫자만 비교하고(공백·구두점·대소문자·목록 기호는 무시), 긴 블록은 24자 조각으로 나눠 60% 이상이 가까이 이어 나오면 찾은 것으로 봅니다. 제목은 PDF 책갈피를 닻으로 삼아 그 자리부터 찾고(목차의 같은 글자에 붙지 않음), 이 플러그인이 넣은 제목 번호가 Word가 그린 번호와 다르면 번호 없이 다시 찾습니다. 표는 칸 글자를 순서대로 찾되 병합을 풀며 반복한 값과 나눈 표가 반복한 머리 행은 바로 그 자리에서만 찾고, 캡션과 함께 표 전체를 쪽마다 상자 하나로 잡습니다. 그림은 캡션의 위치와 그림 쪽 이웃 블록 사이의 영역으로 잡고, 캡션이 없으면 앞뒤 블록이 같은 쪽에 있을 때만 그 사이로 잡습니다(표 밖으로 뺀 그림은 잡지 않음). 못 찾은 블록은 `원본 위치 없음`으로 두고 다음 블록은 마지막으로 찾은 블록 뒤에서 이어 찾습니다.

**Windows 전용인 부분(그림):** EMF·WMF(와 JPEG·GIF·BMP·TIFF) 그림은 Windows PowerShell의 GDI+로 PNG를 만듭니다(원래 크기의 2배, 긴 변 최대 4,000px, 흰 바탕). 그림 전부를 PowerShell 한 번 실행으로 처리합니다. 다른 OS에서는 그 그림을 옮기지 못하고 "그림을 옮기지 못함"에 남깁니다. PNG는 어디서나 그대로 씁니다.

## 옮기는 규칙

| 워드의 것 | 리치오로 |
| --- | --- |
| 제목(스타일·문단의 개요 수준 1~6) | 같은 단계의 제목. `numbering.xml`의 단계별 형식·시작값·`lvlText`로 번호를 계산해 글자 앞에 넣습니다(리치오 자동 번호는 켜지 않음). 계산한 번호는 목차에 남은 번호와 대조합니다. 개요 수준 7~9는 문단으로 두고 알립니다. 제목과 캡션 글자 안의 REF는 링크로 만들지 않고 결과 글자로 둡니다 |
| 본문 문단 | 문단. 굵게·기울임·위첨자·아래첨자는 직접 서식, 글자 스타일, 문단 스타일에서 읽습니다(제목·캡션은 문단 스타일의 서식을 옮기지 않음). 밑줄·색·형광펜은 버립니다. 탭은 빈칸 하나, 문단 안 줄바꿈은 줄바꿈(제목·표 칸·캡션에서는 빈칸) |
| 글머리·번호 목록 | 목록(중첩 포함). `%1.`·`%1)` 모양의 숫자·영문자·로마 숫자 번호는 번호 목록으로, 그 밖의 번호 모양은 원문 표시를 글자에 두고 글머리 목록으로 옮기고 알립니다. 시작 번호는 워드의 계산값입니다 |
| 표 | 리치오 표(첫 행이 머리글). 가로·세로 병합은 값을 반복해 풀고 알립니다. 100행을 넘으면 머리글을 반복해 나누고, 32열을 넘으면 남은 열을 마지막 열에 이어 적고 알립니다 |
| 칸 안의 여러 문단·목록 | ` / `로 이어 한 줄로 적습니다. 번호 목록이면 번호를 앞에 둡니다. 알림은 표마다 하나입니다 |
| 캡션 스타일 문단 | 바로 이웃한 표·그림의 캡션. `Table 3`, `Figure 6.6.4-II`, `표 2-1` 모양이면 고정 번호로 두고 번호와 구분자를 떼며, 아니면 번호 없는 캡션으로 원문 글자를 둡니다. 둘 다 이웃하면 번호의 종류(표·그림)가 맞는 쪽, 없으면 표는 아래·그림은 위의 것 |
| 그림(PNG, EMF, WMF, 끼워 넣은 개체의 미리보기) | PNG 그림 블록. 글과 함께 있던 그림은 문단 뒤로, 표 칸 안의 그림은 표 바로 뒤로 빼고 알립니다. 그림 파일이 없는 도형·차트나 PNG로 바꾸지 못한 그림은 `[그림을 옮기지 못함]`과 캡션 글자를 담은 문단으로 두고 알립니다 |
| REF 필드, 책갈피로 가는 하이퍼링크(본문·표 칸·목록) | 책갈피가 있는 제목, 표·그림 캡션(또는 그림 문단)으로 가는 문서 안 링크 `[표시 글자](#이름표)`. 표시 글자는 필드 결과 글자 그대로입니다. 링크되는 대상에만 이름표를 붙입니다(제목은 앞의 `target` 블록 `sec-…`, 표·그림은 `tbl-…`·`fig-…`). 대상이 표 칸·목록·보통 문단이거나 책갈피가 없으면 글자로 두고 알립니다 |
| 바깥 하이퍼링크 | `http(s)`·`mailto` 주소는 일반 링크, 그 밖의 주소는 글자 |
| 목차, 그림·표 목차와 그 바로 앞의 제목 줄, 머리글·바닥글, 쪽 번호 필드 | 넣지 않습니다 |
| Word 수식(OMML) | 수식 안의 글자를 보통 글자로 두고 알립니다 |
| 글상자 | 그 자리(담은 문단 뒤)의 문단으로 두고 알립니다. 같은 글상자의 예전 형식 사본은 한 번만 옮깁니다 |
| 문서 속성의 제목 | 리치오 문서 제목. 없으면 정하지 않습니다 |
| 숨긴 글자 | 워드가 보이지 않게 둔 글자는 옮기지 않고 알립니다. 문단 표시가 숨김이고 보이는 내용이 없는 번호 문단(워드에서 번호째 숨겨짐)은 옮기지 않되 번호 계산에는 넣어, 뒤따르는 제목이 워드와 같은 번호를 가집니다. 이 문단은 문서 전체에서 한 줄로 알립니다 |
| 기호 글꼴 문자(Symbol·Wingdings) | 해당 유니코드 문자(≤, ≥, ±, ≠, 그리스 문자 등). 표에 없는 문자는 원래 코드로 두고 알립니다 |
| 각주·미주 | 옮기지 않고 알립니다 |

확인할 곳의 종류는 **병합을 푼 표 / 칸 안 문단을 이어 적은 표 / 그림을 옮기지 못함 / 표 밖으로 뺀 그림 / 대상을 찾지 못한 참조 / 수식을 글자로 둠 / 글상자 / 바꿔 적은 그 밖의 것** 여덟 가지입니다. 대상을 찾지 못한 참조는 블록마다 하나로 묶고 표시 글자를 적습니다. 위 표에서 "버립니다"·"넣지 않습니다"라고 적은 것은 알리지 않습니다.

## 하지 않는 것

화면에서 고치기(합치기·나누기·종류 바꾸기), 쪽 고르기, 검토 상태 버튼, 변환 옵션, 설정은 없습니다. 사용자가 같은 이름의 PDF를 직접 내보내 둔 것을 원본 쪽으로 받는 길도 없습니다(옆 파일에 기록이 없는 `X.source.pdf`는 다시 내보내 바꿉니다).

## 확인한 범위

`npm test`는 리치오 없이 합성 표본([`test/fixtures/`](test/fixtures/README.md))으로 제목 번호와 목차 대조, 서식, 2단계 목록, 병합 풀기와 칸 문단 잇기, 캡션 번호, REF 링크와 이름표, 확인할 곳의 종류와 수, 글자 유실 0, 그림을 옮기지 못했을 때, 저장본 블록 경로의 대응과 수가 다를 때의 오류를 검사합니다. 원본 위치 잇기는 합성 입력(블록 목록과 쪽별 줄·상자)으로 순서대로 맞춤, 쪽을 넘는 문단의 상자 둘, 캡션을 포함한 표 상자와 병합을 푼 값·칸 문단 잇기, 못 찾은 블록 뒤에서도 이어지는 맞춤, 목차가 아니라 책갈피 자리의 제목, Word가 그린 제목 번호가 있거나 없을 때, 캡션으로 잡는 그림 영역을 검사합니다. EMF → PNG 검사와 Word로 합성 표본을 내보내 위치를 잇는 검사는 Windows에서만 돌고(Word가 없으면 건너뜀) 다른 OS에서는 건너뜁니다.

원본 쪽은 격리 HTTP Host(리치오 9a803284, Windows, 1440·1920×1080, 밝음·어두움)에서 합성 표본으로 고르기 → 변환 → 목록과 문서가 먼저 보이고 `원본 쪽 준비 중` → 비교 화면으로 바뀜(변환이 끝난 뒤 약 6.5초) → 원본 표 상자를 눌러 문서의 표가 같은 높이로 와서 강조됨 → 확인할 곳 다음 두 번(양쪽이 그 블록으로 감) → 목록으로 돌아가 다시 열기(준비 없이 비교 화면, 약 1.2초)를 확인했습니다. Word가 열지 못하는 워드 문서는 목록 화면에 `Word가 워드 문서를 PDF로 내보내지 못해 원본 쪽을 준비하지 못했습니다.`가 보였습니다. 합성 표본에서는 대상 블록 17개 중 14개를 찾았고, 못 찾은 셋은 Word가 내보낼 때 필드를 새로 고쳐 글자가 바뀐 문단·제목과 글상자 글자가 뒤에 그려져 순서가 어긋난 문단입니다.

같은 Host에서 큰 표본(공개하지 않는 문서, 313쪽, 블록 2,392개)으로 같은 흐름을 한 번 했습니다. Word 내보내기 53.5초(따로 잰 한 번은 83.8초), PDF 6.5MB, 글자 층 읽기 3.2초, 위치 잇기 0.25초, 옆 파일은 약 29KB에서 약 299KB가 됐습니다. 대상 블록 2,291개(제목 676, 문단 1,285, 표 109, 그림 83, 목록 138) 가운데 2,274개를 찾았고 못 찾은 것은 문단 7, 표 3, 그림 7입니다. 못 찾은 것은 Word가 문서 순서와 다르게 그린 글자(표지, 글을 감싸 떠 있는 표, 그림 제목과 바로 뒤의 주석 문단), 캡션이 없는 그림, 글자가 없는 문단입니다. 찾은 것 가운데 무작위 40곳(제목 10, 문단 15, 표 10, 목록 5)을 화면에서 눌러 원본 상자를 눈으로 대조했고 40곳 모두 맞았습니다. 다시 열 때 고르기부터 비교 화면까지 약 5초(문서 보기 표시 1.7초)였습니다. 원본 313쪽을 마우스 휠로 끝까지(약 21초) 스크롤했을 때 50ms를 넘는 프레임이 31~42번 있었고, 대부분 54~74ms, 150~330ms가 8~10번, 첫 연결 쪽(목차 다음) 근처에서 약 1초가 한 번 있었습니다. 쪽 그리기를 끄면 대부분 사라지지만 약 1초 멈춤은 쪽 그리기와 따라가기를 모두 꺼도 남았습니다. 내보내기 전후로 Word 프로세스는 남지 않았고, 빈 문서 하나를 열어 둔 사용자 Word 창은 그대로였습니다.

격리 HTTP Host(리치오 dba55078, Windows, 1440·1920×1080·640px, 밝음·어두움)에서 합성 표본으로 처음 화면 → 고르기 → 변환 → 확인할 곳 줄 누르기(문서가 그 블록으로 감) → 문서 안 링크 Ctrl+클릭(표로 감) → 문서 열기 → 목록으로 돌아가기 → 다시 열기(변환하지 않음) → 다시 변환(확인 뒤 새로 만들고 복구 사본이 남지 않음)을 확인했습니다. 640px에서 가로 넘침은 없었습니다.

같은 Host에서 큰 표본(공개하지 않는 문서, 문단 약 8,400, 표 109, 그림 83)으로 같은 흐름을 한 번 했습니다. 변환 전체 24.0초(구조 읽기 0.3초, 그림 14.7초, 저장 6.6초), 블록 2,506개, 확인할 곳 172곳, 문서 보기 표시 1.6초(다시 열 때 1.3초), 목록 줄을 누른 뒤 이동 10~12ms였습니다. 저장된 문서는 약 0.7MB, 그림 83장은 약 9.3MB이고 공식 `check`는 유효·끊긴 참조 0이었습니다. 제목 번호는 목차에 있는 제목 402개와 모두 일치했습니다. 숨긴 번호 문단과 제목 안 링크를 고친 뒤 화면으로 다시 변환했을 때는 25.3초(그림 15.1초, 저장 6.4초), 블록 2,392개, 확인할 곳 172곳, 문서 안 링크 850개였고 `check`는 같았습니다.

확인하지 못한 것: Word가 없는 PC에서의 화면(실패 문장은 Word가 열지 못하는 문서로만 확인), 10분 시간 제한에 걸리는 경우, 설치형 Desktop, Windows가 아닌 OS의 Host, 다른 회사·다른 양식의 워드 문서, 각주·변경 내용 추적·메모가 있는 문서, 그림이 256개나 32MB(공식 저장 한도)를 넘는 문서, 블록 5,000개를 넘는 문서.
