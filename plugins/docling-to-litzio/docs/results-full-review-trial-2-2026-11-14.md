## 절차와 조건

시작 전에 `git fetch origin`을 실행했고 HEAD와 origin/master는 모두 `ee66c87d109a9f210a47f41644eb5256275b009b`였다. 이전 [중단 기록](results-full-review-trial-2026-11-14.md), 계획·결정, 검수 스킬과 파일 계약을 읽었다.

공개 리치오 최신 master를 새 임시 하위 checkout에 clone했다. commit은 `26c902d3c7d329603d31ea02e3af40e891785b9f`다. Node 24.22.2 / pnpm 12.5.1에서 frozen install, production CLI와 Editor build를 마쳤다. 빌드 크기·플러그인 시간 경고는 있었고 빌드 실패는 없었다. 공개 안내·CLI만 사용했으며 플랫폼 내부 구현을 읽어 우회하지 않았다.

Host 시작 전에 다음 다섯 override를 모두 자기 임시 하위 경로로 지정했다: `LITZIO_DATA_DIR`, `LITZIO_ASSISTANT_CWD`, `LITZIO_ASSISTANT_SETTINGS_FILE`, `LITZIO_DAEMON_DIR`, `LITZIO_PLUGINS_SETTINGS_FILE`. 플러그인 경로도 임시 경로로 지정했다. 최초 선택 포트의 listen이 EACCES로 거부되어 다른 포트에서 시작했다. 실제 AI 시작 전 문제였으며 AI 재시작은 아니다.

플러그인 0.9.0의 변경 없는 사본을 공개 scaffold가 돌려준 제작 폴더에 복사·설치했다. 작업 폴더 설정을 바로잡은 뒤 running/available=true를 확인했다. **실제 AI 전 설정 화면에서 임시 비서 작업 폴더와 설치 검수 스킬을 확인했다.** 대화 UI와 설정에서 Codex `gpt-6.1-terra`, 추론 `high`, 전체 접근을 확인했다.

소유자 결정에 따라 **기존 공급자의 전역 기억·설정이 읽힐 수 있는 조건으로 진행**했다. 이번 비서의 명시적 셸 검색·열람은 0회였다. 자동 주입된 공급자 문맥의 유무·범위는 측정하지 않았다. 공급자 홈·인증·설정을 변경하지 않았고 기억 내용은 기록하지 않는다.

표본은 `fixtures/lsr-1.1`의 북마크 있는 13쪽 공개 PDF와 고정 변환 결과다. 재변환·Docling 서버 기동은 하지 않았다. 사본 document.json의 다음 text만 바꾸고 사본 변환 기록의 document hash를 갱신했다. 주입 정답과 준비 스크립트는 비서 cwd·문서 작업 폴더 밖에 뒀다.

公開 preflight/start/job으로 문서 생성 후 기존 준비 스크립트의 여섯 묶음 선별 부분이 여러 오류가 같은 표에 있는 조건과 맞지 않아 계수 단계에서 실패했다. 문서 생성 자체는 성공했으므로 재생성하지 않았다. 이후 별도 정답표로 기존 읽기 전용 측정기를 실행했다. 준비 실패는 비서 실패 횟수에서 제외한다.

## 비서의 진행

첫 지시는 작업 ID와 함께 “문서의 검수를 끝까지 해 줘. 판단할 수 없는 부분은 남겨 두고 사람이 확인할 것을 알려 줘.”였다. 이후 다섯 턴은 모두 “계속해 줘.”였다. 절차·정답·수정 지시는 추가하지 않았다.

| 턴 | 관측 | 셸 / 공개 operation 시도 |
| --- | --- | ---: |
| 1 | 스킬 읽기, 목록·자료 조회. 9쪽 그림을 uncertain으로 남기고 자체 stop | 7 / 7 |
| 2 | 주입 6개 교정·현재 값 재조회·토큰 재검증. 좌표 계산 입력 1회 거부 후 고침. 수식 3 uncertain, 자체 stop | 17 / 34 |
| 3 | 병합 표·빈 셀·수식·주석을 uncertain으로 제출. 자체 stop | 11 / 39 |
| 4 | 표현 손실 표 5묶음을 uncertain으로 제출. stop 뒤 30범위 미검사를 직접 확인 | 5 / 25 |
| 5 | `page:2`를 material의 groupId로 조회해 실패. 6·7쪽 교정 표 재검사 checkpoint 후 자체 stop, 다시 전 범위 미검사 | 4 / 10 |
| 6 | CLI help·설치 manifest·job 조회. 쪽 자료와 상태 보존 문제를 보고하고 종료. 추가 검수 없음 | 3 / 1 |

operation 수는 저장한 공개 대화 snapshot의 실제 셸 명령·반복 횟수·응답과 제출 이력을 대조해 계산했다. 셸 한 번 안의 여러 CLI 호출도 각각 셌다. 반복문에서 첫 실패 뒤 break한 부분은 실행된 1회만 센다. `plugins.list` 전용 도구 2회와 셸의 `plugins list` 1회는 플러그인 자체 operation 116회에서 제외했다. 전용 도구 2회는 셸 47회에도 포함하지 않았다. 입력 검증에서 거부된 시도까지 포함한 116회이며, 플러그인 handler에 도달한 호출은 115회다.

한 호출의 timeout이나 응답 유실 때문에 멈춘 흔적은 관측하지 않았다. 다만 호출별 시작·종료 시각을 별도 계측하지 않아 최대/평균 operation 지연은 미측정이다. 이번 중단을 작업 지연이나 플랫폼 시간 제한 탓으로 결론 내릴 근거는 없다. 자료 출력 일부는 축약됐고 비서는 파일에 저장해 필요한 부분을 잘라 읽었다.

### 교정과 규칙 준수

읽기 전용 `measure-assistant-acceptance.js`와 현재 인계 검증 결과는 generationValid=true, correctedTargets=6, changes=6, onlyInjectedTargetsChanged=true, protectedTokensRechecked=true였다. 여섯 이력 모두 actor=assistant, readback=true, evidenceRecheck=verified-protected-tokens다. 현재 snapshot은 생성 snapshot에 여섯 교정을 투영한 것과 맞으며 정상 값 변경은 없다. 비교적 쉬운 주입 오류 6/6 결과를 일반 오류 탐지율로 해석하지 않는다.

주입하지 않은 수식 3의 문장 혼입, 표의 기록 없는 수학 값·주석 연결·위첨자 후보를 사람에게 넘겼다. 기존 탐지 후보를 대조한 것으로, 새 오류를 독립적으로 발견했다고 세지 않는다. 추가 교정은 0이다. 빈 셀 7개 전부가 내용 누락이라는 판정도 하지 않았다.

human 선언, human-source-region 교정, 사람 결정, 표현 보존 확인, 최종 완료 발급은 없었다. 문서 직접 수정·재생성이나 근거 없는 빈 셀 채우기 실행은 대화 명령과 검증된 변경 사슬에서 발견하지 못했다. 전역 공급자가 자동 생성하는 세션·로그까지 무변경이라고 주장하지 않는다.

uncertain은 17제출·15고유 묶음이다. 수식 구조·병합 공유 의미·PDF 토큰 없는 그림·셀 기록 부재를 넘긴 것은 스킬의 보수적 근거 규칙에 부합한다. 목차·표 머리·주석의 표현 확인도 사람 역할이므로 넘긴 사실 자체는 위반이 아니다. 다만 정상 표현까지 포함한 이 큐가 모두 실제 오류라는 뜻은 아니며, 이번에는 사람이 검수하지 않아 개별 의미 판단의 정오를 확정하지 않았다.

## 사람에게 남는 양

사람 검수·사람 결정·표현 확인은 실제로 수행하지 않고 현재 반환 자료와 원장을 세었다.

| 항목 | 비서 없는 기준: 이전 중단 기록 | 이번 6턴 뒤 |
| --- | --- | --- |
| 필수 사람 큐 합집합 | 13묶음 / 7쪽 | 15묶음 / 8쪽 |
| 큐 원문 쪽 | 1, 3, 4, 5, 6, 8, 11 | 1, 3, 4, 5, 6, 8, 9, 11 |
| 표현 손실 확인 | 29항목 / 10묶음 | 29항목 / 10묶음 |
| 수식 | 3개 / 3묶음 / 8·11쪽 | 동일 |
| 병합 표 | 2개 / 2묶음 / 4·5쪽 | 동일 |
| 셀 기록 부재 | 7칸 / 2표 / 5·11쪽 | 동일. 5쪽 5칸과 11쪽 2칸. 모두 누락 확정 아님 |
| 그림 글자 층 부족 | 9후보 / 1묶음 / 9쪽 | uncertain 제출로 필수 사람 큐에도 추가 |
| uncertain | 제출 0 | 제출 17, 고유 15묶음. 현재 상태는 stop으로 전부 미검사 |
| 현재 유효 검사 근거 없는 범위 | 17묶음 + 13쪽 | 17묶음 + 13쪽 |
| 남은 주입 오류 | 6 | 0 |

기준 큐에 없던 11쪽 셀 기록 부재 묶음과 9쪽 그림 묶음이 uncertain 제출로 추가되어 15묶음이 됐다. 종류별 수는 중복하므로 합산하지 않는다. 과거 [사람 정책 시험](results-human-policy.md)은 5쪽 반복 수식 4칸·11쪽 수학 값 2칸과 복합 식의 사람 교정 경로를 검증했지만, 이번 사람 교정은 0이다. 필요한 내용 교정은 사람이 원문을 본 뒤 정해야 한다.

화면 확인량의 계산 하한은 **15묶음 방문 위치와 29항목 표현 확인**이다. 한 묶음 방문으로 여러 표현을 볼 수 있으므로 이를 44회의 독립 대조라고 합산하지 않는다. 기존 화면 규칙과 반환된 series/humanQueue를 적용하면 필수 사람 큐는 접히지 않아 전체 **17묶음 행**이 남는다. 이번에는 실제 검수 화면에서 15묶음을 클릭하며 사람 검수를 하지 않았다. 따라서 이는 화면 규칙에 따른 계산이지 실제 클릭 횟수·소요 시간 실측이 아니다. 사람 결정·교정·재확인·완료까지의 총 클릭 수는 미측정이다.

큐 쪽 비율은 7/13(53.8%)에서 8/13(61.5%)로 늘었다. 이것만 보면 5쪽을 생략하는 듯하지만 **13/13쪽이 미검사**여서 생략할 근거가 없다. 이번 실행은 사람의 전수 확인 부담 감소를 입증하지 못했다. 확실히 줄어든 것은 알려진 주입 오류 6개를 사람이 직접 고칠 필요뿐이다.

최종 gate는 ready=false, uncovered=30, human=15, blocking=0, expressionUnconfirmed=29, failures=0, tokenDifferences=0이다. blocking=0과 tokenDifferences=0은 수식·누락·표현 의미의 보증이 아니다.

## 막힌 곳과 원인 분류

| 분류 | 관측과 해석 |
| --- | --- |
| 플러그인 | material은 실제 groupId를 받으며 페이지 범위 자료 조회 작업은 manifest에 없다. `page:2` 호출은 일반적인 실패 문구만 반환했다. 범위 원장에는 전 쪽이 있으나 전 쪽 검사 자료를 얻는 경로의 안내가 부족하다 |
| 스킬 | 묶음 순회·교정·판단 불가 절차는 있지만 후보 없는 쪽까지 검수하는 방법이 없다. 예산 부족 시 stop을 권하지만 stop/resume의 전 범위 무효화와 결합해 이어가기 비용을 설명하지 않는다 |
| 리치오 | 실행·공개 CLI·편집·readback은 동작했다. 페이지 조회와 stop의 동작은 이 플러그인 계약의 문제로, 플랫폼 내부 결함이라는 증거는 없다. 입력 거부와 operation 실패의 일반 문구는 원인 파악에 부족했다 |
| 모델의 절차 선택 | 전체 요청 중 반복해서 자체 stop을 택했고 마지막에는 명세를 확인했다. 불가능한 페이지 ID를 묶음 ID로 시도했다. 왜 각 턴에서 멈췄는지 추론 예산·내부 원인을 측정하지 않았으며 판단 품질 일반화는 하지 않는다 |

**관측:** 5턴째 재검사 checkpoint 직후 상태가 생겼다가 stop 후 전부 미검사가 됐다. **계약상 해석:** [human-review의 사건 표](../../../../contracts/docling-to-litzio/human-review.md)는 stop/resume 때 전 범위·사람 확인 무효화를 명시한다. 비서가 보고한 “상태 초기화 문제”를 곧바로 구현 버그로 채택하지 않는다. 안전 규칙 자체와, 그 규칙을 알지 못한 채 평범한 턴 종료에 stop을 쓰는 운영 절차가 맞물린 병목이다.

1. 스킬에 stop/resume의 무효화와 사용자 턴 종료의 차이를 명시하고 불필요한 자체 stop을 줄이는 절차를 정한다. 안전 계약을 약화하는 변경부터 하지 않는다.

4. 위 조건을 고친 뒤에만 동일 표본의 후속 시험을 별도로 승인받아 측정한다. 이번 결과로 수백 쪽 사용성·교정 품질 수락을 대신하지 않는다.

## 정리와 검증 경계

6턴 모두 완료 상태를 관측한 뒤 시험 브라우저를 닫았다. listener의 소유 PID와 시험 Host 명령줄을 대조하고 해당 프로세스 트리만 종료했다. 출력에서 공급자 하위 프로세스 종료를 확인했고 시험 포트 listener 0개를 확인했다. 재귀 삭제는 쓰지 않았으며 임시 산출물은 보존했다. 설치된 리치오·기존 daemon·사용자 자료는 조작하지 않았다.

저장소에는 이 결과 문서 하나만 추가한다. 주입판·원시 대화·캡처·산출물은 넣지 않는다. 다른 플러그인과 fixtures·docs/progress.md는 변경하지 않았다. 제품 코드 변경이 없으므로 새 단위 검사·전체 회귀는 실행하지 않았으며, 현재 인계·교정 대상의 읽기 전용 측정은 수행했다. 사람의 실제 검수와 시각 수락은 수행하지 않았다.
