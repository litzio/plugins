## 실제 화면과 처리 코드

세 격리 환경 변수 `LITZIO_DATA_DIR`, `LITZIO_ASSISTANT_CWD`, `LITZIO_ASSISTANT_SETTINGS_FILE`을 모두 자기 시험 하위 폴더로 지정한 HTTP Host에 설치했다. cliEntry 없이 작업 폴더만 설정해 available=true, 실제 pickPath 대화에서 LSR converted 폴더 선택 → 입력 확인 → 생성(113블록·2그림·31손실·15묶음)을 확인했다. 선택 취소는 입력을 유지한다. 절대 선택 경로도 realpath 경계 검사 뒤 상대 경로와 fingerprint로 생성하며 외부 폴더는 거부한다.

기존 비교 결과의 현재 셀 경로를 DocumentView에 그대로 전달한다. 셀 강조는 PDF 근거 상자의 정밀도를 바꾸지 않는다. PDF는 여전히 표 전체 영역일 수 있다. 문서 열기는 opened/refused 응답을 처리하며 손 편집 시 인계 차단 안내를 유지한다. 기본 설정의 CLI 위치 입력을 제거했고 처리 코드의 context.cli 우선 및 옛 Host의 cliEntry fallback은 유지했다.

## 결정적 LSR 수락과 제한

화면에서 PDF 11쪽을 직접 보고 식 (3)을 세제곱근·합 상한 9·항 지수 3으로 교정했다. 공식 correction-submit/readback/history가 applied였다. PDF 5/11쪽의 빈 수식 셀 여섯 개도 공개 작업의 사람 원문 영역 근거로 채웠다. 총 일곱 교정이며 임의 문서 overwrite는 하지 않았다.

표현 보존 확인과 묶음·쪽 checkpoint는 이전 LSR 정책의 가정을 재사용한 결정적 제출이다. note에 절차 시험이며 전체 의미 품질/실제 AI 검수 증거가 아님을 남겼다. 실제 AI·재변환·Docling 서버는 호출하지 않았다. 200쪽 이상 실사용·제목 전수 정확성·사람 부담 측정도 미수행이다.

## 검사·캡처

최신 빌드 CLI를 지정한 전체 검사 132개 중 127 통과, 5 corpus 환경 skip, 실패 0. 절대 선택 경로의 같은 fingerprint·상대 경로 반환·외부 거부 검사를 추가하고 관련 7개 검사도 모두 통과했다. 설치와 CLI 없는 설정은 실제 Host에서 확인했다. C0–C9·계약 v1.2와 완료 무효화 처리 코드는 변경하지 않았다.

결정적 제출 도중 대조 화면의 주기적 읽기와 동시에 진행한 일부 쓰기가 uncertain receipt로 끝났다. 원장을 다시 읽어 실제로 기록된 항목과 없는 항목을 구분한 뒤, 대조를 닫고 남은 제출을 했다. receipt만으로 성공을 판정하지 않았고 자동 재전송을 제품에 추가하지 않았다. 이 동시 사용의 경합은 남은 사용성 한계다. 플랫폼에 새 능력이 필요한지는 플러그인 자체 잠금 경합을 먼저 분리해 재현해야 하므로 플랫폼 결함으로 단정하지 않는다.

새 플랫폼 부족으로 확정한 항목은 없다. 이번 표본에서 가로 overflow가 발생하지 않은 큰 표/수식, 일반 탭 미저장 편집의 보호와 실제 동시 편집은 여전히 미수락이다. fixtures·다른 플러그인·진행 기록은 변경하지 않았고 임시 자료는 보존한다.
